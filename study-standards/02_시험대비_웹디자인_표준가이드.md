## 1. 전체 웹앱 폴더 및 3페이지 연동 아키텍처

각 과목의 `07_시험대비/{중간|기말}/` 폴더(및 웹 배포 폴더)는 메인·O/X·다지선다 3개 페이지를 기본으로 연결한다. 주관식 제작 원본·로컬 수식 자산·별도 모의시험 페이지는 과목의 출제 유형에 맞춰 추가한다.

```text
07_시험대비/중간/
├── {과목명}_중간고사_Notion.html   # 로컬 직접 열기용 메인 통합본
├── index.html                     # 웹 서버/라우팅 호환용 메인 통합본 사본 (Notion.html과 100% 동일)
├── ox/
│   └── index.html                 # Step 2: 전 범위 원자 개념 1:1 O/X 전수검증 앱 (window.OX_ITEMS 데이터 소스 겸용)
├── multiple-choice/
│   └── index.html                 # Step 3: 전 범위 4지선다(단일·복수·사례) 집중 훈련 앱
├── written/                       # 주관식·코드 JSON, 빌더, 메인 템플릿(해당 과목)
├── mock-exam/index.html            # 별도 시험 페이지로 구성할 경우
├── assets/                        # 로컬 수식 엔진·분석 그림·공통 재풀이 코드
└── final-audit/                    # 재현 가능한 검증 스크립트·결과·필수 fixture
```

- **개념 데이터 실시간 교차검증 (`#coverageSource` iframe)**:
  - 메인 `index.html`과 `multiple-choice/index.html`은 `<iframe id="coverageSource" src="./ox/index.html?concept-source=1" hidden></iframe>`(메인 기준, 다지선다에서는 `../ox/index.html?concept-source=1`)을 통해 `ox/index.html`의 전체 원자 개념 배열(`window.OX_ITEMS`)을 불러온다.
  - 이를 통해 대응 ID가 빠진 개념을 탐지한다. 개념 목록과 문제 데이터는 로컬 파일에서도 읽히도록 내장하고, 보충 문제를 작성한 뒤 지문·보기·해설이 실제 개념을 평가하는지 대조하여 **`coverageMissingAfterSupplement = 0`**을 확인한다. iframe이나 ID 일치만으로 원문 내용까지 무누락이라고 판정하지 않는다.

## 2. 디자인 철학 및 컬러·타이포그래피 토큰 (`:root`)

미니멀하고 가독성이 뛰어난 **Notion 스타일 흑백(Monochrome) Study OS** 테마를 기본으로 하며, 정답(초록)·오답(빨강)·그림 배지(파랑)에만 절제된 시맨틱 컬러를 사용한다.

```css
:root {
  --bg: #ffffff;
  --sidebar: #fbfbfa;
  --text: #191919;
  --muted: #787774;
  --faint: #9b9a97;
  --line: #e9e9e7;
  --soft: #f7f7f5;
  --hover: #efefed;
  --dark: #222222;
  --radius: 4px;
  --sidebar-w: 252px;
  --topbar-h: 45px;
  --page-w: 920px;
  color-scheme: light;
}
```

- **폰트 패밀리**: `ui-sans-serif, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", "Segoe UI", sans-serif`
- **기본 본문 크기**: `15px`, `line-height: 1.65`, `word-break: keep-all`
- **수식 렌더링**: MathJax v3 (`tex-mml-chtml.js` 또는 `tex-svg.js`) 필수 탑재
  - 인라인 수식: `\(...\)`, 디스플레이 수식: `\[...\]`
  - 문제 풀이 뷰(`body.view-problems`)에서는 수식 크기가 줄바꿈을 깨뜨리지 않도록 `.q-title mjx-container, .solution mjx-container, .objective-text mjx-container`의 크기를 본문 비율에 맞게 조정한다.

## 3. 상단 고정 바(Topbar), 좌측 사이드바(Sidebar) 및 전역 유틸리티

### 3.1 상단 고정 바 (`.topbar`, `height: 45px`)
- **좌측**: 모바일 메뉴 버튼(`#menuBtn`, `☰`), 과목 아이콘(`.crumb-icon`) + 과목명 브레드크럼(`.crumb`).
- **중앙 학습 탭 (`.app-tabs`)**:
  1. `개념 정리` (`data-view="notes"`, `href="./index.html"`)
  2. `O/X` (`data-view="ox"`, `href="./ox/index.html"`)
  3. `다지선다` (`href="./multiple-choice/index.html"`)
  4. `예상문제` (`data-view="problems"`, `href="./index.html?view=problems"`) — 실전 문제 + 기출 5세트 + 서술·단답 통합
  5. `오답 정리` (`data-view="mistakes"`, `href="./index.html?view=mistakes"`)
- **우측 액션 (`.top-actions`)**:
  - 상단 미니 타이머 배지(`#timerPill`, 시험 모드 동작 시 표시)
  - 전역 검색 버튼(`#searchBtn`, `⌕ 검색 ⌘K`)
  - 모든 토글 일괄 열기/닫기 버튼(`#moreBtn`, `▤`)
  - 인쇄/PDF 저장 버튼(`#printBtn`, `⎙`)

### 3.2 좌측 고정 사이드바 (`aside.sidebar`, `width: 252px`)
`개념 정리` 뷰(`body.view-notes`)에서만 표시되며, `예상문제` 및 `오답 정리` 뷰에서는 자동으로 숨겨져 넓은 풀이 화면을 확보한다.
1. **Study OS 그룹**:
   - `⌂ 시험 대시보드` (`#dashboard`), `→ 지금 먼저` (`#now`), `▤ 개념 노트` (`#concepts`), `★ Summary·강조 지도` (`#priority`), `▣ 교안 빈칸` (`#blanks`), `□ 예상문제` (`./index.html?view=problems` + 문항 수 배지 `#expectedCountSide`), `◉ 개념 O/X` (`./ox/index.html` + 개념 수 배지), `↺ 오답 노트` (`./index.html?view=mistakes` + 오답 수 배지 `#mistakeCountSide`), `✓ 직전 체크리스트` (`#checklist`).
2. **개념 목차 그룹**:
   - 단원별 앵커(`#c1` ~ `#cN`, `#scope`)로 즉시 스크롤 이동하며, `IntersectionObserver`를 통해 현재 읽고 있는 단원의 사이드바 링크에 `.active` 클래스가 자동 부여된다.
3. **하단 전체 학습 진도 바 (`.side-progress`)**:
   - 체크리스트 완료 수 + 문제 풀이(`done`) 완료 수를 합산하여 실시간 퍼센트(`#sideProgressFill`, `#sideProgressText`)를 표시한다.

### 3.3 전역 검색 모달 (`#searchOverlay`, 단축키 `⌘K` / `Ctrl+K`)
- 페이지 내 모든 섹션, 개념 토글(`details.toggle`), 예상문제 지문 및 해설을 실시간 검색한다.
- 검색 결과 클릭 시 해당 섹션 또는 문제로 즉시 뷰를 전환하고, 닫혀 있는 `<details>` 토글을 자동으로 열어(`open = true`) 스크롤 이동한다.

### 3.4 이중 안전장치(CSS + JS) 기반 뷰 전환 (`setPageView` & `updateSectionVisibility`)
웹 서버(`https://`)와 로컬 파일(`file://`) 양쪽에서 탭 전환 시 화면이 개념 정리 화면에 머무는 버그가 절대 발생하지 않도록 **명시적 CSS 선택자**와 **JS 인라인 스타일 직접 제어**를 동시에 적용한다.

1. **CSS 명시적 섹션 은닉**:
   - `:not()` 복합 선택자에만 의존하지 않고, `body.view-problems` 및 `body.view-mistakes` 상태에서 `#dashboard, #now, #concepts, #checklist, #sources, .divider, .sidebar`를 각각 `display: none !important;`로 명시적 은닉 처리한다.
2. **JS 직접 제어 (`updateSectionVisibility(view)`)**:
   - `setPageView(newView)` 호출 시 각 섹션 요소의 `style.display`를 직접 갱신(`problems` 뷰는 `flex`, `mistakes` 뷰는 `block`, `notes` 뷰는 기본값 복원)한다.
   - `history.pushState`는 반드시 `try { ... } catch(e) {}`로 감싸 로컬 `file://` 프로토콜에서의 SecurityError로 인해 스크립트가 중단되지 않게 방어한다.

## 4. 개념 정리 뷰 (`body.view-notes`) 7대 필수 섹션 규격

개념 정리 화면은 단순 요약본이 아니라 교안·전사·수식·빈칸·오류 교정을 모두 담은 완결형 레퍼런스 문서로 구성한다.

1. **`#dashboard` (시험 대시보드)**:
   - 과목 상징 아이콘(`.page-icon`), 제목(`h1`), 부제(`.subtitle`).
   - **Notion 속성 표 (`.properties`)**: `◷ 시험 일시`, `⌖ 장소·좌석 안내`, `◎ 출제 방식·문항 수 태그`, `✎ 준비물(OMR 여부 등)`, `≡ 확정 범위`, `× 제외 범위`, `◇ 검증 기준` 7개 행.
   - **최신 공지 콜아웃 (`.callout.black`)**: 시험 문항 수·유형·제외 범위 핵심 요약.
   - **2열 현황 카드 (`.dash-grid`)**: 좌측 `나의 준비도` 대형 퍼센트(`#readinessNumber`) + 프로그레스 바 / 우측 `시험까지 D-Day` 실시간 카운트다운(`#daysLeft`, `#countdownDetail`).
2. **`#now` (지금 먼저 할 일)**:
   - 시험 전 최우선 실행 4단계 테이블(`01 Summary 회수` → `02 교안 빈칸 전체 회수` → `03 상황→개념 판정` → `04 실전 시간 맞춰 풀기`) 및 추천 학습 루프 콜아웃.
3. **`#priority` (Summary · 교수 강조 출제 지도)**:
   - 3열 우선순위 기준 카드(`.priority-grid`: `★★★ Summary 직접 제시`, `★★★ 전사 반복·직접 강조`, `★★☆ 상황→개념 판별`).
   - 교안별 핵심 출제 포인트 및 우선도(`★★★`/`★★☆`) 요약 테이블.
4. **`#c1 ~ #cN` (단원별 전수 개념 노트)**:
   - 단원 핵심 통찰 인용구(`.quote.block`) 및 전체 프로세스 플로우(`.flow` > `.flow-step`).
   - 각 세부 주제별 **아코디언 토글 (`details.toggle.block`)**:
     - 정의·성질·주의점 리스트(`.note-list`)
     - 핵심 공식 및 기호·차원·성립 조건 박스(`.formula`)
     - 경쟁 개념/모형 비교 테이블(`.study-table`)
     - 교안 오탈자·전사 보완 설명 콜아웃(`.callout`)
5. **`#blanks` (교안 빈칸 완전정리 · 페이지별 답)**:
   - 원본 슬라이드의 모든 빈칸 상자(`???`), 예제 계산 질문, 연습문제를 **원본 페이지 번호(`.blank-page`) + 질문 원문 + 검산된 정답 및 출제 변형 포인트** 표로 전수 수록한다.
   - 하단에 교안 원문 오기를 바로잡은 **빈칸 해석 및 검산 교정 원칙 콜아웃**을 배치한다.
6. **`#scope` (확정 제외와 경계)**:
   - 공지상 시험에서 제외된 항목(`.callout.black`)과, 교안에 이름만 등장하여 개념 수준만 알아두면 되는 경계 항목(`.callout`)을 명확히 구분한다.
7. **`#checklist` & `#sources` (시험 직전 체크리스트 & 근거 자료)**:
   - 자료를 보지 않고 구술·손계산할 수 있는지 점검하는 체크박스 리스트(`#checklistBox`, `localStorage` 자동 저장) 및 하위 마크다운 근거 문서 6종 카드 그리드(`.source-grid`).

body.view-problems { overflow: hidden; overscroll-behavior: none; }

body.view-problems #problems { height: 100%; display: flex !important; flex-direction: column; }
body.view-problems .database { flex: 1; min-height: 0; margin: 0; display: flex; flex-direction: column; }

### 5.1 상단 필터 툴바 (`.db-toolbar`) 및 2단계 드롭다운 토글 (`▾` / `▴`)
- **기본 유형·속성 필터 버튼**:
  - `전체` (`all`), `단일선택` (`single`), `복수선택` (`multi`), `O/X` (`ox`), `서술·단답` (`essay` — 서술형 포함 시), `계산` (`calc`), `사례형` (`case`), `교안 빈칸` (`blank`), `핵심` (`priority`), `기출 90제` (`past`), `📊 그림 문제` (`visual`), `미응답` (`unanswered`)
- **2단계 토글 드롭다운 버튼 (화살표 `<span id="...Arrow">▾</span>` 필수 포함)**:
  1. **`오답 ▾` (`#againFilterBtn`)**:
     - **1회 클릭 (다른 필터 → 오답 진입)**: 오답 목록만 표시하고 **재풀이 바는 접힌 상태(`▾`)**로 둔다. 탭 진입만으로 답안을 지우거나 새 회차를 시작하지 않는다.
     - **활성 상태에서 한 번 더 클릭 (2회 클릭)**: `오답 재풀이` 바를 펼쳐(`▴`) 진도·`오답만 다시 풀기`·`재풀이 종료`를 표시한다. 같은 탭을 다시 누르면 바만 접는다. 접고 펼칠 때 목록 재필터링·문항 이동·초기화·재채점을 실행하지 않고 현재 선택·입력·진도를 유지한다.
  2. **`⏱ 실전·기출 N문항 시험 ▾` (`#toolbarExamBtn`)**:
     - **1회 클릭**: 실전 모의고사 안내 진입(기본 1세트 로드, 시험 시간은 공지 기준으로 표시) 및 검은색 **실전·기출 모의고사 바(`#examBar`)** 펼침(`examBarOpen = true`, 화살표 `▴`).
     - **시작·진행 제어**: 안내 진입·바 펼치기만으로 답안이나 타이머를 새로 시작하지 않는다. 명시적인 시험 시작 버튼으로 마감 시각을 저장한다.
     - **시험 진행 중 한 번 더 클릭**: 시험이 종료되지 않고 **`#examBar`만 접히고 펼쳐지는 토글(`▾`/`▴`)**로 동작한다. 제출·종료·초기화는 명시적인 동작으로만 수행하며, 시간 만료 시에는 자동 제출한다.

### 5.2 오답 탭의 재풀이 제어 (최신 공통 규약)

- **노출 위치**: O/X·다지선다·단답/서술/코드·기출형 각각의 `오답` 탭을 선택한 뒤 **같은 탭을 한 번 더 눌러 바를 펼쳤을 때만 `오답만 다시 풀기`를 표시**한다. `오답·애매` 또는 `오답·복습`을 사용하는 경우 해당 복습 탭 안에 둔다. 전체·미응답·북마크·개념 화면의 공통 도구 행에는 상시 노출하지 않는다.
- **시작 전**: 기존 오답과 해설을 조회할 수 있다. 버튼을 눌러야 해당 문항의 새 답안과 닫힌 해설로 재풀이를 시작한다. 원래 답안은 보관한다.
- **진행 정보**: 펼친 바에 이번 회차 문항 수, 채점한 수, 해결한 수, 자동 저장 상태를 표시한다. 탭의 화살표와 `aria-expanded`를 실제 접힘/펼침 상태와 일치시킨다. 해결한 문제 때문에 현재 목록이 갑자기 바뀌지 않도록 회차 ID 목록은 유지한다.
- **다음 회차**: 같은 버튼을 누르면 미채점 문항의 이전 기록을 먼저 복원하고, 최신 결과상 남은 오답만 새 회차로 모은다. 해결한 문제는 제외한다.
- **종료**: `재풀이 종료 · 전체 문항` 또는 다른 상태 탭으로 이동하면 재풀이를 종료한다. 채점을 확정한 새 결과는 반영하고, 미채점 문항의 이전 답안·채점을 복원한다.
- **빈 목록**: 오답이 없다는 안내를 보여준다. 전체 문제를 오답으로 대신 불러오거나, 작성하지 않은 문제를 임의로 오답 처리하지 않는다.
- **제어 연결**: 버튼은 실제 시작·종료 함수와 연결한다. 이전의 ‘오답 답안 일괄 삭제’ 구현을 복사하지 않는다. 상태·보존·예외 처리는 10절을 따른다.

### 5.3 실전·기출 모의고사 바 (`#examBar`) 규격 및 5세트 선택기
- **1열 (현재 시험 정보 및 제어)**:
  - 세트 제목(`#examTitleLabel`: `자체 제작 기출형 N문항 — K세트`, 실제 기출 원문이 있으면 출처 구분), 실시간 카운트다운 배지(남은 시간: 과목별 공지의 시험 시간), 완료 배지(`#examProgressBadge`: `M / N 완료`), **`[↺ 현재 답안 초기화]` (`#examResetAnswersBtn`)**, **`[✕ 시험 종료 (전체 문제)]` (`#examExitBtn`)**.
- **2열 (기출 1~5세트 & 무작위 추출 선택 바)**:
  - **`[기출형 N문제 1세트]`** ~ **`[기출형 N문제 5세트]`** 버튼 또는 세트 선택기를 둔다. **`[🎲 무작위 N문제 추출]` (`#examRerollBtn`)**은 학습용 추출 기능을 제공하는 경우에만 배치한다.
  - 각 세트 버튼 클릭 시 해당 세트(`q.pastSet === K` 등 안정적 세트 ID) 문항만 정확히 로드하고 활성 버튼 스타일을 갱신한다. 진행 중 시험의 세트 변경·무작위 추출은 비활성화하고, 저장된 시험/연습·세트별 기록과 제출 답안을 보존한다.

## 6. 문제 카드(객관식·O/X·그림·서술형) 및 선지별 상세 해설 규격

### 6.1 문제 헤더 (`.q-head`) 및 시각·그림 박스 (`.visual-box`)
- **문항 헤더**: 문항 번호(`Q1`, `Q101`, `Q+OX009`), 문제 지문(`.q-title`), 메타 태그(`.q-meta`: 단원 태그, `단일선택`/`복수선택`/`O/X` 태그, `기출 K세트` 다크 태그, `📊 그림문제` 블루 태그, `누락 보충` 다크 태그).
- **문제 전체를 포괄하는 분석자료 박스 (`.visual-box` 등)**:
  - 지문 다음에 필요한 자료를 인라인 SVG·구조화된 표·읽기 전용 출력/준비 코드·로컬 원문 그림으로 제공한다. 자료는 문항 전체의 판단 조건을 포함해야 하며, 형식을 맞추기 위해 무관한 패널을 추가하지 않는다.
  - 원문 그림 파일을 쓰면 배포 폴더에 포함하고 출처·페이지·축·단위·범례를 보존한다. 이미지를 사용할 수 없는 문항에는 관련 없는 대체 이미지를 넣지 않는다.
  ```html
  <div class="visual-box" style="margin:10px 0 6px;padding:10px 12px;background:#f8fafc;border:1px solid #cbd5e1;border-radius:8px;">
    <div style="font-size:11.5px;font-weight:700;color:#334155;margin-bottom:6px;">📊 [제시 그림] 도식 제목 및 비교 구도 안내</div>
    <svg viewBox="0 0 480 125" style="width:100%;max-width:460px;height:auto;display:block;margin:0 auto;font-family:sans-serif;">
      <!-- (A) 정상 vs (B) 위반 vs (C) 위반 등 문제 전체 맥락을 포괄하는 벡터 도식 -->
    </svg>
  </div>
  ```

**문제용 자료의 정답 단서:** 이미지·표·제목·캡션·접근성 대체 텍스트에 물음의 답을 미리 표시하지 않는다. 답이 적힌 강의 슬라이드는 문제용으로 전체 조건을 유지해 재구성한다. 수치·단위·축·변수 정의를 없애 불완전한 문제가 되지 않게 하고, 판정·분류·풀이 결론은 정답 공개 후에 제시한다. [제작 가이드의 정답 단서 검사](03_시험대비_개념정리_및_문제출제_표준가이드.md#answer-hint-audit)를 함께 따른다.

**보기 자체의 시각적 단서:** 정답만 자세하거나 유일한 오답만 길어지는 패턴을 막는다. 정보 항목·문장 구조·어조·조건·단위·수식/코드 표기를 비교하고 데스크톱·모바일에서 실제 줄바꿈을 확인한다. 길이를 맞추기 위한 군더더기나 필요한 자료 삭제는 피한다. 정답 공개 전에는 정오 색상·아이콘·근거·단원 소주제·문항 제목·접근성 이름이 요구 답을 직접 알려주지 않아야 한다. 원본·기출형의 보기별 해설과 실제 채점도 대조한다. [보기 품질 기준](03_시험대비_개념정리_및_문제출제_표준가이드.md#option-quality-standard) · [전수 검토 순서](03_시험대비_개념정리_및_문제출제_표준가이드.md#question-quality-review-workflow)를 따른다.

### 6.2 객관식·O/X 선지 및 선지별 상세 해설 (`.objective-option` & `.objective-explain`)
- **단축키 지원**:
  - `O/X` 문항: `,` = O, `.` = X (선택 즉시 채점, 정답 후 이동 설정은 7.1절의 앱 동작을 따름)
  - `단일선택` 문항: 숫자키 `1` ~ `4` (선택 즉시 채점, 자동 이동은 기본 해제하고 선택 설정으로 제공)
  - `복수선택` 문항: 숫자키 `1` ~ `4`로 복수 토글 후 `Enter` 또는 `[선택 완료]` 버튼으로 채점
  - 문항 이동: `←` (`ArrowLeft`), `→` (`ArrowRight`)
- **정답 공개 전 보기 표시**: 모든 보기의 기본 글꼴·배경·굵기·여백·코드 서식을 동일한 규칙으로 적용한다. 수학적 강조나 데이터의 의미가 아닌 정답 여부 때문에 서식이 달라지지 않게 한다. 난이도·정답/오답 이유·개념 대응 이름은 풀이 전 단서가 되지 않도록 해설 영역에서 공개한다.
- **채점 후 시각 피드백 및 선지별 개별 해설 (필수)**:
  - 채점 즉시 내가 고른 정답(`.selected.correct`), 놓친 정답(`.missed`), 내가 고른 오답(`.selected.wrong`) 스타일이 적용된다.
  - **모든 보기(1~4번 각각) 아래에 왜 그 보기가 정답인지(`✓`) 또는 왜 틀렸는지(`×`)를 설명하는 `.objective-explain` 블록이 반드시 함께 표시되어야 한다.**
  - 하단에는 전체 핵심 해설 배너(`.objective-result.show.good/.bad`)와 **`[이 문제 다시 풀기]`** 버튼(`.retry-one.show`)을 배치한다.

### 6.3 서술·단답형 모드 UI 컴포넌트 규격 (`.answer-box`, `.solution`, `.grade-group`)
6단계 학습 파이프라인의 **Step 4 (서술·단답형 문제)** 또는 서술형 시험 과목에서는 다음 컴포넌트를 제공한다.
- **답안 작성란**: `<textarea class="answer-box" placeholder="핵심 정의, 수식, 단위, 절차를 직접 적어보세요..."></textarea>` (`localStorage`에 작성 답안 자동 저장).
- **모범 답안 및 채점 기준 토글**: `[정답·해설 보기]` 버튼 클릭 시 `.solution.open` 박스가 열리며 **모범 답안 + 필수 포함 키워드 + 검산 절차**를 표시한다.
- **3단계 자기채점 버튼 (`.grade-group`)**:
  - `[완벽 이해 (done)]`, `[애매함 (unsure)]`, `[다시 풀기 (again)]` 3개 버튼을 제공한다. `unsure`와 `again`은 통합 오답 정리·복습 목록에서 함께 조회할 수 있지만, **`오답만 다시 풀기`의 주관식 대상은 `again`만** 포함한다. `unsure`를 자동으로 틀린 문제로 바꾸지 않는다.

   - 상단에는 현재 오답·복습 목록으로 이동하는 탐색 버튼을 둔다:
     - **`[✏️ 오답 문제 바로 풀기 (N문제)]` (`#goSolveMistakesBtn`)**: 클릭 시 `예상문제` 뷰의 `오답` 필터로 즉시 이동해 오답만 연속 풀이.
   - `오답만 다시 풀기` 버튼과 새 회차를 곧바로 시작하는 링크는 통합 오답 정리·개념·전체 탭에 두지 않는다. 해당 문제은행의 오답 탭을 다시 눌러 펼친 제어 바 안에만 표시한다. 탐색 버튼과 개별 문항 링크는 기존 답안을 지우거나 회차를 시작하지 않는다.
   - 하단 오답 리스트(`#errorLog`)의 각 항목(`.error-item`) 클릭 시 `jumpToQuestion(id)`가 실행되어 해당 문제 카드로 즉시 이동.
2. **인쇄 및 PDF 변환 (`@media print`)**:
   - 상단바, 사이드바, 검색창, 버튼류를 모두 숨기고(`.topbar, .sidebar, .db-toolbar, .quiz-controls { display: none !important; }`), 본문 폭을 `100%`로 넓혀 깔끔한 시험 직전 요약지 형태로 출력되게 한다.


## 9. 문제 초기화 버튼과 단계별 기록 보존 (2026-10-17 보완)

- O/X·다지선다의 `↺ 문제 초기화`는 상태 필터·단원 버튼과 같은 항상 보이는 도구 행에 둔다. 접힌 검색·도구 메뉴 안에만 숨기지 않는다.
- 버튼의 존재뿐 아니라 이벤트 연결, 취소 시 보존, 실행 후 답안·정오·진도 초기화, 새로고침 후 유지까지 검증한다.
- 각 단계의 초기화는 해당 단계 답안·정오만 지우고 북마크·개념 체크리스트·다른 단계 기록을 보존한다. 확인창에 지워지는 범위를 명시한다.
- 단일 문항 초기화와 오답 묶음 재풀이는 별도 동작이다. 일반 연습의 단일 초기화는 해당 문항만 지운다. 오답 재풀이의 미채점 상태와 제출 완료 시험의 원본은 10절에 따라 보존한다. 새로고침이 새 답안을 다시 지우지 않게 한다.
- 로컬 링크는 `ox/index.html`, `multiple-choice/index.html`처럼 실제 파일을 지정한다. 문제 데이터는 HTML에 내장하여 iframe·fetch 실패로 풀이가 막히지 않게 한다.
- 다지선다 정답 후 자동 이동은 기본 해제하고 선택 설정으로 제공한다. 모든 보기의 해설을 충분히 읽을 수 있어야 한다.


## 최신 답안 언어·주관식 제작 기준 (2026-10-17)

- “용어를 영어로 작성”은 교안에서 영문으로 제시한 명칭을 쓰라는 뜻이다. 설명·해석·수치 답안이나 원래 한글인 개념까지 임의로 영어로 바꾸지 않는다. 요구 영문 용어마다 교안 페이지 근거를 기록한다.
- 주관식은 답안 작성→모범답안·상세 풀이 열기→배점 항목 체크→완벽 이해/애매함/다시 풀기의 흐름으로 제공한다. 자유 서술·코드를 실행·의미 분석 없이 자동 채점한다고 표시하지 않는다.
- 배점 항목 합계와 문항 총점을 일치시키고, 수식·단위·조건·부호·자유도의 실수별로 부분점수를 구분한다.
- 코드에는 실행 가능한 모범 코드와 동등한 대안의 인정 범위를 적는다. 코드 구문 검사와 실제 R 실행 검증 여부를 구분해 기록한다.

### R 코드 문항의 스크립트 편집창 (2026-10-17)

- 코드 영역은 R 스크립트 파일 탭·줄 번호·고정폭 글꼴·문법 색상을 갖춘 Source 편집창 형태로 표시한다. 메인 학습 UI의 기존 디자인을 유지하며 코드 영역에 한정한다.
- 실제 R 구문을 사용하고 공백·개행·들여쓰기를 그대로 보존한다. 최상위 문장은 0칸, 여러 줄 함수 호출의 인자는 2칸 들여쓰며 닫는 괄호는 함수 호출 시작 위치에 맞춘다. 연산자와 이름 있는 인자의 = 양옆에는 공백을 둔다.
- 빈칸 번호는 입력칸의 placeholder로 표시한다. 코드 앞뒤에 별도 번호나 폼 라벨을 끼워 넣지 않고 입력한 코드가 해당 줄의 기준선에 놓이게 한다.
- 완성 답안도 같은 편집창과 들여쓰기·문법 색상을 사용한다. 긴 코드 줄은 편집창 내부에서 가로 스크롤하며 코드 줄을 임의로 접지 않는다.

## 10. 오답 재풀이 상태·저장·시험 기록 보존

### 10.1 대상 판정

| 문제 유형 | 재풀이 대상 | 제외·구분할 상태 |
|---|---|---|
| O/X·다지선다 | 채점 완료 후 틀린 문항 | 맞힌 문항·아직 미채점인 문항·북마크만 한 문항 |
| 단답·서술·코드 자기채점 | `again`(다시 풀기) | `done`(완벽 이해), `unsure`(애매함), 미채점 |
| 기출형·모의시험 | 각 문항의 최신 확정 결과가 오답 또는 부분점수인 문항 | 오래된 오답보다 최신 정답을 우선한다. 미채점 주관식은 제외한다. |
| 명시적 복습 표시 | 사용자가 직접 복습 표시한 문항 | 정답 문항도 포함할 수 있으므로 `오답·복습`으로 표시하고 자동 오답과 구분한다. |

제출 후 0점으로 확정된 미작성 문항은 오답에 포함할 수 있다. 단순히 미응답·미채점이라는 이유만으로 자동 오답 처리하지 않는다. 모의시험은 전체 세트의 최신 결과를 모으되 제출한 시험 답안 자체를 수정하지 않는다.

### 10.2 회차 저장 및 복원

1. 시작 시 **회차 ID 목록·시작 시각·현재 문항 ID·기존 답안/채점 보관본·새 입력·채점 확정 여부**를 저장한다. 보기 번호 대신 안정적인 문항·보기 ID로 연결한다.
2. 처음 시작할 때만 새 답안·선택 해제·닫힌 해설을 준비한다. 렌더링·1초 타이머·새로고침·직접 링크 재진입 때 반복 초기화하지 않는다.
3. 새로고침하면 같은 회차, 현재 문항, 선택/텍스트/코드 빈칸 입력, 추가 답안, 채점 진행을 복원한다.
4. 답안이나 채점 기준을 바꾸면 해당 재채점의 확정 표시와 확정 시각을 무효화한다. 다시 확정하기 전에는 해결한 문제로 집계하지 않는다. 주관식 자기평가와 체크 점수를 별도로 관리하는 경우 그 관계를 명시한다.
5. 회차 종료·다른 상태 탭으로 이동·다음 회차 시작 시, **미채점 문항은 이전 답안·점수·채점 기준·해설 공개 상태를 복원**한다. 새로 채점을 확정한 문항만 최신 결과로 반영한다.
6. 북마크·개념 체크리스트·다른 문제 유형/과목의 기록은 유지한다. 회차 보관본에 보존 한도를 두는 경우 현재 미채점 문항의 원복 자료를 먼저 삭제하지 않는다.
7. 저장 키는 과목·중간/기말·문제은행·스키마 버전을 구분한다. 다른 과목에 레퍼런스 코드를 복사할 때 기존 과목의 저장 키를 그대로 사용하지 않는다.
8. 저장 실패는 사용자에게 표시한다. 다른 탭의 저장 갱신 후에도 재풀이 제어기가 현재 저장 객체와 같은 보관본을 참조하게 한다. 삭제된 문항 ID는 유효성 검사하며 문항 순서 변경으로 답안이 엇갈리지 않게 한다.

### 10.3 모의시험·직접 링크 예외

- 시험 진행 중에는 오답 재풀이와 세트/모드 전환으로 시험을 벗어나지 못하게 한다. 제출 완료 시험에서 ‘현재 문제 다시 풀기’를 눌러도 제출 답안을 삭제하지 않고 별도 연습 답안으로 연결한다.
- 타이머는 저장한 절대 마감 시각과 현재 시각의 차이로 계산한다. 새로고침·바 접기·백그라운드 이동으로 시간이 늘지 않으며, 만료되면 한 번만 자동 제출한다.
- `?retryWrong=1` 같은 직접 링크의 새 회차 시작은 선언·저장소·화면 준비가 끝난 뒤 한 번만 처리한다. 처리한 시작 요청은 URL에서 제거하여 종료 후 새로고침할 때 다시 시작하지 않는다. 직접 링크나 새로고침으로 재풀이를 이어가더라도 제어 바는 기본 접힘 상태로 표시하며 활성 오답 탭을 누르면 펼친다.
- 진행 중인 회차가 있으면 URL 재진입으로 답안을 지우지 않고 이어 푼다. 주관식 해설을 열거나 채점 기준을 수정한 것만으로 채점 완료로 간주하지 않는다.

## 11. 웹앱 최종 검수와 인계

- 보기·난이도는 [제작 가이드의 난이도 기준](03_시험대비_개념정리_및_문제출제_표준가이드.md#difficulty-review-standard)과 [문항별 검수 기록](03_시험대비_개념정리_및_문제출제_표준가이드.md#question-quality-record)을 사용한다. 정답 공개 전/후 화면을 구분하고, 보기 길이 지표만으로 난이도를 판정하지 않는다.
- 최종 내용·코드·수식·분석자료 검수는 [제작 기준의 최종 검수표](03_시험대비_개념정리_및_문제출제_표준가이드.md#final-quality-gate)를 따른다. 버튼 존재·구문 검사만으로 기능 검수를 완료하지 않는다.
- 모든 문항을 실제 브라우저에서 순회하여 지문·자료·해설·채점 기준을 확인한다. 모바일에서는 긴 수식·넓은 표·여러 패널 그림·긴 코드·재풀이 제어 영역을 별도로 검사한다. 페이지 전체가 잘리거나 가로로 밀리지 않도록 하며 표·코드의 필요한 내부 스크롤은 허용한다.
- 독립된 검증용 브라우저 프로필에서 정상·오답·부분점수·미채점·빈 목록 데이터를 구성해 재풀이/저장/초기화/타이머를 실제 조작한다. 사용자가 풀던 브라우저 기록으로 초기화 검사를 하지 않는다.
- `file://`에서는 HTML에 내장한 데이터와 로컬 수식·이미지가 정상 표시되는지 검사한다. 게시용 HTTP 복사본에서도 전체 문항을 검수한다. `file://`의 fetch 제한과 앱 자체 오류를 구분한다.
- 수식 엔진·그림·필수 참고자료는 배포 폴더 안에 포함하고 경로·파일명 대소문자·404를 검사한다. 별도 로컬 강의자료 폴더에만 존재하는 파일을 게시 지문이 참조하지 않게 한다.
- 빌더·JSON·템플릿을 고치고 재생성한다. 생성 HTML만 수정해 다음 빌드에서 고친 내용이 사라지지 않게 한다. 마지막 수정 후 영향을 받는 검사를 다시 실행하고 검증한 파일과 게시 복사본의 일치 여부를 확인한다.
- 사용자가 지정한 게시 순서에 맞춰 최종 자료를 반영한다. 게시한 경우 원격 기본 브랜치·게시 빌드 완료·공개 파일의 일치·실제 공개 주소의 핵심 동작까지 확인한 뒤 완료라고 알린다.

### 12.1 반응형·인쇄 확인

- 데스크톱 2열/다열 카드와 사이드바는 작은 화면에서 1열·모바일 목차로 전환한다. 상단 학습 탭은 가로 스크롤 또는 폭 조절로 전부 접근할 수 있어야 한다.
- 레퍼런스는 개념 화면의 900/620px, 주관식·코드·재풀이의 600px 분기를 사용한다. 값만 복사하지 말고 실제 제목 길이·도표·언어별 코드와 360~390px 휴대폰/태블릿/데스크톱에서 잘림을 확인한다.
- 전체 페이지의 불필요한 가로 넘침은 막되 긴 수식·표·코드는 해당 영역 안에서 읽을 수 있게 한다. 작은 높이·가상 키보드 표시 상태에서도 답안과 제출/이동 버튼에 접근할 수 있어야 한다.
- 인쇄/PDF에서는 고정 높이·내부 스크롤·상단바/사이드바·버튼을 해제해 자료·표·그림·코드·해설이 페이지 밖으로 사라지지 않게 한다. 문제용/해설용 출력이 다르면 출력 범위를 명시하고 빈 입력칸과 완성 코드를 구분한다.

## 13. 디자인 검수 결과 기록

디자인 검수 문서에는 화면별 구성요소, 실제 확인한 화면 폭, 정상/빈 목록/채점 전후/재풀이 바 접힘·펼침/시험 진행·제출 상태, 수정 내역과 캡처 또는 재현 절차를 남긴다. 설명을 작성했다는 이유만으로 클릭·저장·인쇄·반응형 검증을 통과했다고 기록하지 않는다. 제작 순서와 산출물은 [제작 가이드 12절](03_시험대비_개념정리_및_문제출제_표준가이드.md#production-workflow)을 함께 따른다.


다음 과목에 구현을 옮길 때는 [제작 가이드의 시작 설정표와 자료 대응표](03_시험대비_개념정리_및_문제출제_표준가이드.md#next-subject-setup)를 작성한다. 레퍼런스의 과목명·저장 키뿐 아니라 빌더/검증 스크립트의 고정 개수·시험 시간·원본 경로·실행 환경까지 교체하고 해당 과목 자료로 검증한다.

2026-10-18 보기 품질 기준은 [최신 보기·기출형 검수](../interactive-psychology-midterm/23_보기품질_문항검수.md)를 참고한다. 다음 과목에서는 제작 가이드 4.3·5.1~5.2·8.2·11.3절의 난이도·보기·전파·기록 절차를 해당 과목 자료로 수행하고, 이 과목의 통과 수치나 정답 배분을 복사하지 않는다.

## 계산 정밀도 안내와 변경 답안 보존

손계산 문항의 제시 로그·최종 반올림 자리·정확한 분수 인정 여부는 해당 지문과 채점 기준에서 확인할 수 있게 한다. 공통 정밀도 안내는 작게 접을 수 있게 두되 정답이나 계산 결과를 미리 보여 주지 않는다. 실제 R Source·출력 창은 공백·들여쓰기와 출력의 필요한 정밀도를 유지한다.

수치가 바뀐 연습 답안은 기존 기록을 별도 보관한 뒤 영향 문항만 새로 풀도록 한다. 진행/제출한 모의시험 화면은 원래 문항·해설과 남은 시간으로 유지하고 이전 버전임을 표시한다. 새 응시에서 새 문항을 적용한다. 안내의 보관본 내려받기, 저장 공간 부족, 새로고침·다중 탭 동기화도 검수한다. 계산 문항의 상세 제작 기준은 공통 제작 가이드 14절을 따른다.

## 그림 판독·번호별 단답 입력

중요한 대응표·도식은 정답 라벨을 제거한 완결된 그림과 번호별 단답 입력칸을 제공한다. 그림·질문의 (가)/(나), 빈칸 번호·입력 라벨·모범답안·배점을 맞춘다. 정답을 보기 전 입력란에 답안 예시를 미리 넣지 않는다. 일반 단답 저장·수정 시 채점 해제·초기화·오답 재풀이·시험 제출 잠금에 동일하게 연결하고, 모바일에서 모든 입력칸과 전체 그림을 확인할 수 있게 한다. 개념군 연결 외에 세부 유형 검수도 공통 제작 가이드 15절에 따라 수행한다.


## 서술형 문항 개편 시 화면과 저장 규약

- 서술형 내용은 제작 가이드 **16절**의 단일 평가 초점·연관된 요구·질문/답안/배점 일치 기준을 따른다. 지문에서 빠진 요구를 해설·채점표에만 남기지 않는다.
- 필요한 사례·분석자료만 같은 카드에 둔다. 별개 실험·논문을 한 카드에 합치지 않으며, 한 시기만 묻는 문제에 전체 연대표를 붙여 정답을 노출하지 않는다.
- 문항 ID와 새 평가 초점을 추적하고, 내용이 달라진 연습 문항의 답안·자기채점·체크된 배점·해설 공개 상태를 함께 새로 시작한다. 이전 기록은 저장 성공을 확인한 보관본으로 남기고 다른 문항의 기록은 보존한다.
- 이미 진행·제출한 모의시험은 해당 버전의 문항·자료·해설·배점·답안·마감 시각으로 유지한다. 재응시에서 새 문항을 사용하며, 이전 내용의 오답 결과를 새 내용의 문항에 연결하지 않는다. 여러 구버전과 새로고침·다중 탭 저장도 확인한다.
- 문항을 분리해 늘렸다면 필터·직접 이동·현재 문항 초기화·전체 수·해설·채점 항목·모바일 화면·수식 렌더링을 재검수한다. 사용자 브라우저의 실제 학습 기록을 테스트에 사용하지 않는다.
- 로컬 보완 후에는 사용자가 최종 푸시를 명시적으로 요청할 때까지 게시하지 않는다.


## 강의형 코드 입력과 한 줄 작성 UI

기존 코드 편집창은 부분 빈칸과 한 줄 전체 작성 모두 지원한다. 한 줄 작성에는 목표 결과와 읽기 전용 준비 자료를 제시하고, 함수 호출 전체를 쓰는 입력란 하나를 둔다. 두 형식을 필터로 구별하고 모범답안의 모든 문장을 한 줄씩 설명한다. 강의가 콘솔 입력을 파란색으로 표시했다면 입력/모범 코드를 파란 고정폭 글씨로, `>` 프롬프트는 실행 소스 바깥 요소로 표시한다. 입력과 출력·준비 자료의 역할은 라벨로도 구분한다.

문법 때문에 필요한 개행·들여쓰기는 유지하지만 짧은 함수 호출을 임의로 여러 줄로 늘리지 않는다. 긴 줄은 코드 창 안에서 가로 스크롤하고, 모바일에서도 문서 전체가 옆으로 넘치지 않게 한다. 입력·저장·초기화·채점·오답 탭 재풀이·구버전 시험 보존은 한 줄 형식에서도 같은 규약을 따른다. 실행 의미가 같은 문항은 줄 배치나 해설만 바뀌었다고 기존 답안을 지우지 않는다. 내용·검증은 제작 가이드17절을 따른다.


## 시험 직전 압축본 화면

제작 가이드18절에 따라 시간별 목차·판별표·손계산 풀이·강의형 코드·짧은 인출 점검을 하나의 페이지에 배치한다. 답 가리기/펼치기는 키보드로 조작할 수 있게 하고, 인쇄에서는 접힌 풀이도 포함한다. 문제 풀이의 고정 높이 카드를 그대로 적용하지 않고 세로로 읽을 수 있게 구성한다. 표·코드의 내부 스크롤과 모바일 화면을 확인하며, 이 페이지를 열거나 인쇄해도 기존 시험·학습 저장소를 건드리지 않는다.

## 코드 실행·상태 판단 문제의 읽기 전용 코드 영역 (2026-10-21)

- 실행 과정은 지문 속 긴 명령 나열 대신 **물음 → 필요한 조건/입력 → 실제 코드 → 보기/답안** 순서로 제시한다. 객관식·단답형도 필요한 코드를 제출 전부터 읽을 수 있어야 한다.
- 실제 문법의 고정폭 글꼴·줄바꿈·들여쓰기·문자열 공백을 보존한다. 읽기 전용 제시 코드, 학생 작성란, 실행 출력, 모범 코드를 라벨로 구분한다. 줄 번호는 코드의 일부나 복사 문자열에 섞지 않는다.
- Notebook 셀은 경계와 실행 순서를 표시한다. 셀 제목·프롬프트는 별도 UI 또는 유효한 주석으로 두며 Python 코드 줄에 “A 셀:” 같은 문법 아닌 표기를 붙이지 않는다. 색상만으로 입력·출력을 구분하지 않는다.
- 조건에는 초기 상태·함수 정의/호출·데이터·경로 기준·파일 모드/내용·커널 재시작 등 해당 물음에 필요한 것만 넣는다. 코드 영역을 잘라 중요한 준비 문장이나 끝부분을 숨기지 않는다. 이미지가 필요하면 문제 전체 조건을 포함하고, 실제 코드로 읽는 편이 명확하면 텍스트 코드 영역을 우선한다.
- 출력 판단 문제의 답·예외명·최종 상태는 제출 전 주석/제목/출력창에 노출하지 않는다. 목표 출력이 주어진 작성 문제와 구별한다. 검색에는 지문과 실제 제시 코드를 포함하되 숨긴 정답을 검색용 힌트로 노출하지 않는다.
- 긴 줄은 코드 내부 가로 스크롤, 긴 문제는 카드 내부 세로 스크롤로 읽는다. 좁고 낮은 화면에서 코드와 모든 보기·입력·채점/이동 버튼에 도달할 수 있어야 한다. 인쇄에서는 고정 높이/스크롤 잘림을 해제해 코드와 해설을 포함하고 출력 후 접힘 상태를 복원한다.
- 표시만 명확히 하는 보완은 기존 답안·북마크·초안을 유지한다. 조건·정답 의미가 달라진 경우에는 공통 기록 보존 규약을 적용한다. 저장·새로고침 뒤에도 제시 코드와 풀이 기록이 유지되는지 확인한다. 내용/실행 검수는 제작 가이드17.1절을 따른다.

## 시험대비 창 안의 상세 해설 UI와 검수 (2026-10-24)

## 의미 없는 추가 코드 빈칸 정리와 기록 이전 (2026-10-24)

빈칸 선정은 제작 가이드21절(`meaningful-code-blanks`)을 따른다. 임의 숫자·문자열·지정된 변수명을 베껴 쓰는 입력칸은 만들지 않는다. 같은 의미를 여러 칸으로 쪼개지 않고 필요한 코드는 고정 텍스트로 보여 준다. 의미 있는 조건/경계값·자료형 판단은 남기며 교안 원문 빈칸은 별도 구분과 필터로 보존한다.

문항을 제외하거나 빈칸을 고정하면 현재 목록·유형별 개수·이동 순서·검색·오답 재풀이 회차·문제/해설 MD를 함께 갱신한다. 남은 칸은 연속 번호로 표시하고 정답/상세 설명과1:1로 연결한다. 이전 답안을 새 번호에 안전하게 옮기며 수정 전 문제·답안·당시 정오를 설정의 기록 보관 영역에서 확인할 수 있게 한다. 제외한 ID의 북마크를 지우거나 다른 문제를 초기화하지 않는다. 미채점 초안·진행 중 재풀이·종료 시 이전 답안 복원·저장 후 재접속·반복 새로고침을 독립 프로필에서 확인한다.


### 완성 코드의 실행 결과 문제 표시

결과 예측의 객관식/단답은 빈칸 입력 UI를 억지로 재사용하지 않고 전체 코드·들여쓰기·필수 입력/파일·실행 조건을 풀이 전에 보여 준다. 실제 관측할 출력/상태와 답안 형식을 명확히 묻고,해설은 명시적 열람/채점 뒤에 공개한다. 여러 줄 출력 보기의 공백/개행·repr표현을 유지해 다른 보기가 같은 모양이 되지 않게 한다. 긴 코드/보기와 모든 자료는 카드 내부에서 끝까지 읽을 수 있게 하며 기존 저장 답안·미완성 입력·북마크를 보존한다. 유형별 실제 출제 판단과 추가/제외 기준은 제작 가이드21.1절을 따른다.

### 빈칸 위치와 해설의 실제 화면 대조 (2026-10-25)

빈칸 입력칸이 다른 단어 한가운데 끼어 `pr[입력칸]`·`[입력칸]esult`처럼 보이면,정답을 넣어 코드가 복원돼도 완료로 보지 않는다. 함수/변수/인덱스의 의도한 구간을 해당 언어의 토큰/문맥과 대조하고 제작 가이드21.2절을 적용한다. 서식·문자열 일부를 쓰는 정당한 문항은 정확한 예외 범위와 이유를 기록한다.

풀이 전 입력칸의 실제 줄·앞뒤 고정 코드·좌표를 독립 검수한 원문 구간과 대조하고,정답 입력/채점 뒤에는 모든 칸의 정답·이유·완성 문장과 전체 풀이가 대응하는지 확인한다. 코드·정답을 합쳐 복원되는지만 보는 검사로 대신하지 않는다. 데스크톱·좁은 화면에서 문자열/들여쓰기/입력·이동/채점 접근을 보존한다.

정답/번호가 같은 위치 수정은 저장 키나 다른 문항을 초기화하지 않는다. 수정 전 문제·답안·정오와 재풀이 이전 답안을 보관하고 현재 답안·초안·북마크·진행 회차는 유지한다. 수정 기록은 설정의 기록 영역에서 알아볼 수 있게 표시하고 재접속·반복 새로고침·재풀이 종료/복원·나중 입력 변경 뒤에도 과거 기록이 바뀌지 않는지 검증한다.

### 빈칸별 목표의 완결성 표시 (2026-10-25)

중립 지문 아래의 ‘완성할 동작’에는 모든 숨긴 작업을 풀 수 있는 요구사항을 제공한다. 여러 출력 중 마지막 것만 설명하거나,선택할 구간을 주지 않고 ‘주어진 구간’이라고 쓰지 않는다. 필요한 경우 행별로 출력 대상·선택 범위·순서·변환 방향을 명시하되 정답 코드/함수 이름을 미리 알려주지 않는다. 생성 코드의 줄 번호가 바뀌면 이 안내와 검수 대응도 함께 갱신한다.

학생 화면에서 새 목표가 풀이 전에 읽히고 코드/입력칸과 연결되는지 확인한다. 기존 정답·해설·입력/정오·북마크는 문구 변경으로 초기화하지 않는다. 요구사항의 내용 검수는 제작 가이드21.3절을 따른다.

### 중복 통합 후 목록과 풀이 기록 (2026-10-25)

교안 원문 예제와 중복 추가 연습을 통합할 때에는 제작 가이드21.4절을 적용한다. 전체/유형별 목록·검색·원문 필터·문항 이동·오답 회차는 실제 활성 문제만 표시하고 같은 예제를 빈칸 위치만 달리해 반복 노출하지 않는다. 전체 코드의 출력 판단처럼 다른 평가 목표가 있는 문항은 해당 목적을 지문에서 명확히 한다.

설정의 수정 전 답안 영역에서 제외한 ID·남긴 ID·이전 문제·답안/정오를 확인할 수 있게 한다. 제외 문항의 정답 이력을 남긴 문항에 자동 복사하지 않으며, 유지한 답안·초안·북마크를 전체 초기화하지 않는다. 진행 중인 재풀이에서 제외 ID만 빠지고, 종료/취소·새로고침 후에도 보관 기록이 유지되는지 확인한다. 통합 후 각 빈칸의 실제 위치·입력/채점·문장별/실행별 상세 해설·좁은 화면을 점검한다. 중복을 없애면서 필요한 목표·입력/파일 조건이나 전사 강조 해설까지 잃지 않는다.

### 예제형 ‘완성할 동작’과 코드 작성 단위 (2026-10-25)

기존 시험대비 화면의 ‘완성할 동작’에 예제 전체의 입력·처리 순서·반환/출력·파일/상태 조건을 읽기 쉽게 제시한다. 화면 배치를 모방하라는 요청으로 임의 해석하지 않는다. 원문에서 준 입력별 결과와 별도 연습용 목표 출력은 명확히 구분하고, 같은 코드 입력 창에서 필요한 조건을 확인할 수 있게 한다. 자세한 내용 기준은 제작 가이드21.5절을 따른다.

추가 코드 연습은 함수명 한 단어 대신 실제 식·조건식·인수를 포함한 호출·필요한 문장을 작성하게 한다. 한 예제의 관련 단계는 한 문제 안에 두며, 입력칸은 긴 코드 단위를 입력·수정할 수 있어야 한다. 고정 코드와 들여쓰기, 빈칸 번호/해설/실행 줄의 대응을 보존한다. 원문 빈칸의 기존 형식은 구별하여 유지한다.

결과 예의 실제 공백·개행·파일 내용을 보존하고, 근삿값/난수 조건을 고정 출력으로 오해하게 만들지 않는다. 전체 정답 코드와 상세 풀이를 열기 전에도 과제 조건은 보여 준다. 출력 예측이나 용어 단답 화면에는 해당 정답을 노출하지 않는다. 문항의 키가 바뀐 경우 이전 기록은 설정에서 확인하게 하고, 새 코드 문항에 과거 단어 정답 이력이 자동 이식되지 않게 한다.

### 통합 후 제시 조건·빈칸·해설 재검수 (2026-10-25)

제작 가이드21.6절을 따른다. 학생 화면의 고정 코드·‘완성할 동작’·입력/파일/조건만으로 각 빈칸의 과제 목표를 결정할 수 있어야 한다. 숨긴 인수·문자열/튜플 값·인코딩·파일의 초기 상태·입력 범위를 정답이나 PDF에서 찾아야 하는 문항은 보완한다. 원문 빈칸의 표기를 구분할 의미 조건도 같은 창에서 제시한다.

풀이 전의 입력칸 위치와 앞뒤 코드, 풀이 후의 빈칸 전체 정답·이유·완성 문장·출력/파일·실행 단계를 전수 대조한다. 해설에서 코드에 없는 재읽기를 수행했다고 쓰거나 실제 목록 변환을 뷰 생성만으로 설명하지 않는다. 기존 호출 복사로 끝나는 추가 빈칸은 의미 있는 식/문장으로 조정한다. 데스크톱/좁은 화면과 코드 스크롤에서 조건·입력·채점·이동을 확인한다.

문안과 해설만 바뀐 기록은 유지하고, 답의 단위가 바뀐 문항만 수정 전 답안에 보관한다. 초안·채점·이전 재풀이 답안/북마크·저장/새로고침·반복 이전 방지를 검증한다. 과거 기록의 문항 수/검수 결과와 현재 결과를 명확히 구분한다.

## 객관식·개념 단답형의 보기와 상세 풀이 표시 (2026-10-25)

내용 검수는 제작 가이드22절(`mc-short-semantic-audit`)을 적용한다. 강의자료·전사의 실제 평가 판단을 활성 문항에 연결하고, 같은 판단을 유형만 바꿔 반복하지 않는다. 문항 수/태그가 같다는 이유로 누락·중복 검수를 완료하지 않는다.

- 풀이 전에는 전체 코드·필수 입력/준비 파일·표·셀 실행/초기 상태와 관측할 대상을 보여 준다. 지문·배지·힌트는 정답을 대신 알려주지 않는다. 표/출력/보기를 이미지로 제공할 경우 문제 전체에서 필요한 자료가 포함되어야 하며 무관한 자료를 넣지 않는다.
- 객관식 보기는 같은 관측 대상과 비슷한 정보 단위를 유지한다. 실제 공백·개행·따옴표·빈 문자열을 보존해 서로 다른 보기가 같은 모양으로 합쳐지지 않게 한다. 정답만 유독 길거나 자세한지 화면에서 확인하되 무관한 문구로 길이를 맞추지 않는다.
- 채점/명시적 열람 후 모든 보기에 정오와 판단 근거를 제공한다. 상세 풀이에는 이 문항의 조건·값·실행 순서·현재 상태와 결론을 연결한다. PDF는 보조 원문이며, 보기의 오개념과 코드 문장별 진행을 같은 창에서 끝까지 확인할 수 있어야 한다.
- 단답의 요구 형식·강의 표기·허용 답과 채점은 일치해야 한다. 용어·수치/단위·코드·출력의 입력 방식을 구별한다. 코드/수식/표의 문법·들여쓰기·공백/개행을 유지하고, 실제 출력과 해설용 식별 표시는 구분한다.
- 중복 통합/의미 변경은 수정 전 문제·답안/정오·재풀이 이전 답안을 보관하고 활성 목록·검색·이동·회차에서 갱신한다. 문안/해설만 고쳤다는 이유로 답안·초안·북마크를 초기화하지 않는다. 다른 문항의 이력을 새 문항에 복사하지 않는다.

독립 검수 프로필에서 현재 활성 객관식/단답을 전수 확인한다. 풀이 전후·보기별 근거·필수 자료·입력/채점·저장/새로고침·오답 재풀이와 좁은 화면을 포함한다. 역사적 보관본 검사와 현재 화면 결과를 구분해 기록한다.

## 마우스 위치와 무관한 본문 휠 스크롤 (2026-10-25)

문제 카드의 흰 여백뿐 아니라 ‘완성할 동작’·입력/출력 예·준비 파일·교안 코드/빈칸 입력·표·보기·상세 해설 위에서도 세로 휠이 본문으로 이어져야 한다. 긴 내용은 끝까지 읽고 다시 위로 돌아올 수 있어야 한다. 스크롤바를 직접 잡거나 마우스를 여백으로 옮겨야 하는 구조로 만들지 않는다.

코드/표/출력의 내부 가로 스크롤은 유지한다. 가로 읽기 영역에 두 축의 `overscroll-behavior: contain`을 함께 걸어 세로 휠까지 가두지 않는다. 가로 경계를 제한할 필요가 있으면 X축만 제한하고 Y축은 상위 본문으로 연결한다(예: `overscroll-behavior-x: contain; overscroll-behavior-y: auto`). 세로로 넘치는 별도 패널은 그 안을 읽은 뒤 상위로 이어지는 동작을 확인한다. 우선 브라우저의 기본 스크롤 연결을 사용하고 광범위한 wheel 차단/강제 이동을 추가하지 않는다.

검수는 스크롤 위치를 코드로 바꿨다는 사실만으로 통과시키지 않는다. 실제 포인터를 각 영역/입력칸 위에 놓고 휠을 위·아래로 보내 본문 이동을 확인한다. 코드/표의 가로 시작·중간·끝에서도 세로 이동이 이어지고 가로 휠은 내부 가로 읽기를 유지해야 한다. 데스크톱·좁은 화면, 해설을 접은/펼친 상태에서 확인하고 테스트한 브라우저/화면 크기를 기록한다.

입력 포커스·기존 답안/초안·채점/북마크·키보드 이동·가로 읽기를 보존한다. 인쇄에서는 고정 높이/내부 스크롤 때문에 코드·표·해설이 잘리지 않아야 한다. 스크롤만 수정할 때 저장 키/문항 리비전을 바꾸거나 답안을 초기화하지 않는다. 레이아웃 원본과 생성 HTML을 함께 갱신하고 재현된 실패와 수정 후 결과를 남긴다.

## 압축본의 필수 경로·선택 회상·출력 확인 UI (2026-10-25)

내용·유형·실행 검수는 [제작 가이드18.1~18.6절](03_시험대비_개념정리_및_문제출제_표준가이드.md#cram-review-and-execution)을 따른다. 기존 과목의 시각적 일관성 안에서 빠르게 읽을 필수 복습과 막힐 때 펼칠 전체 코드/회상·근거를 구분한다. 특정 과목의 단원 수·카드/문항 수·시간표·언어·저장 키를 다음 과목의 고정 구조로 만들지 않는다.

- 개념 노트/문제 화면에서 압축본으로 가는 별도 진입과 시간별 목차를 제공한다. 권장 시간의 합과 순서를 알 수 있게 하고, 선택 예제를 펼쳤다는 이유로 필수 경로를 계속 늘리지 않는다.
- 질문·완성할 동작·전체 제시 코드·필수 입력/파일/실험 자료·모드/초기 상태·관측 대상을 정답보다 먼저 확인할 수 있게 둔다. 원문 빈칸과 예제 기반 재선정은 다른 배지/설명으로 표시한다. 재선정 칸의 실제 줄·앞뒤 코드·정답·해설을 대조한다.
- 코드가 포함된 객관식도 보기와 선택 지시가 있어야 한다. 출력 구분용 `/` 등의 약속은 명시하고 실제 공백·개행을 보존한다. 단답은 요구 언어·용어/값/문장 단위가 분명해야 하며, 제목/배지에 답을 미리 쓰지 않는다.
- 풀이를 열면 각 빈칸의 답·완성 코드·실수 근거, 객관식 모든 보기의 판단, 직접 단답의 정확한 표기, 문항별 실행 순서를 같은 창에서 읽는다. 일반 코드 예시에도 실제 출력·출력 없음·파일 기록을 별도로 확인할 수 있게 한다. 코드 파일 저장과 화면 출력, 반환값과 객체 변경을 섞지 않는다.
- ‘해설 모두 펼치기’는 자식 해설의 속성만 바꾸지 않는다. 필요한 상위 접힘도 열어 실제로 보이게 하고, 개별 열기·닫기와 키보드 동작을 함께 확인한다. 학습용 전체 코드/추가 근거와 답을 숨기는 영역의 역할을 구별한다.
- 목표·보기·코드/빈칸·출력·준비 자료·해설 어느 영역 위에서도 세로 휠이 본문으로 이어져야 한다. 긴 코드는 내부 가로 읽기를 유지하고 바깥 화면이 가로로 밀리지 않게 한다. 기존 `pointer-independent-wheel-scroll` 기준을 적용한다.
- 인쇄에서는 접힌 코드·정답/해설·표/수식도 누락시키지 않고 긴 줄이 잘리지 않게 한다. 인쇄 후 열람 전의 개별 접힘 상태를 복원한다. 인쇄 모드 확인과 실제 인쇄물/페이지 시각 확인은 검수한 범위대로 구분한다.

독립 프로필에서 초기 숨김→개별/일괄 열람→선택 코드/보기/결과 확인→닫기·키보드→좁은 화면/휠→인쇄/복원→기존 학습 화면 복귀를 점검한다. 스크롤을 코드로 이동시켰다는 사실만으로 휠이 작동한다고 하지 않는다. 기존 답안·초안·북마크·타이머·재풀이 상태를 보존하고, 로컬 직접 열기/배포 방식에서 필요한 자산과 링크가 작동하는지 확인한다. 생성 HTML만 수정하지 말고 편집 원본·템플릿·MD·대응/검수 기록과 함께 갱신한다.
