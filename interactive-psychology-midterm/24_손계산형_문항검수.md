# 손계산형 문항·정밀도·답안 보존 검수

검수일: 2026-10-18. 사용자가 계산기를 사용하지 않는다고 확인했고, 로그 사용은 가능하되 소수 첫째 자리 수준의 손계산이 가능하도록 요청했다. 공식 시험 공지의 문구와 사용자 확인을 구분했다.

## 수정 범위와 원칙

다지선다 8·단답/서술/R 13·기출형 12·O/X 7, 총 40문항을 보완했다. [문항별 변경 목록](final-audit/handcalc-changes.json)과 [이전/현재 원문](final-audit/handcalc-compatibility.json)을 보관한다. 기존 188개 개념군·정답 보기 ID/순서·시험 배점을 유지한다. 이후 추가된 세부 빈칸 단답은 [25번](25_세부항목_빈칸단답_검수.md)을 따른다.

- 필요한 로그는 문제 안에 제공한다. 예: `log2(5)≈2.3`, `log2(1.25)≈0.3`, `log2(11)≈3.5`. 제시 근삿값을 그대로 사용하고, 중간값을 유지한 뒤 최종 소수만 첫째 자리로 나타낸다.
- 길어지는 나눗셈은 정확한 분수를 인정한다. Hick 처리율은 `20/3 또는 6.7`, 변형은 `25/3 또는 8.3 bits/s`다. 회귀 R²와 F도 분수 답안을 인정하고 채점 기준에 명시했다.
- 표본 수는 마지막에 최소 정수로 올린다. 파일럿 포함·총 인원·추가 인원을 구별한다. 원본 예제의 수치를 바꾼 경우 출처에 손계산용 변형이라고 적는다.
- 표준편차 직접 계산은 작은 정수 자료로, 회귀 직접 계산은 작은 표본·단순한 정수/분수 자료로 구성한다. 자유도·분모·단위·잔차 부호·적용 조건을 생략해 쉽게 만들지 않는다.
- 교안의 p값·계수·실제 R 출력은 판독용 자료의 정밀도를 유지한다. 모든 수치를 무조건 소수 첫째 자리로 반올림하지 않는다. 손계산 근삿값과 실제 로그 계산은 서로 섞지 않는다.

## 기존 기록과 동작

변경된 연습 문항의 답안·채점은 원본 전체를 별도 보관한 뒤 해당 문항만 갱신한다. 다른 답안·북마크·개념 체크는 유지한다. 변경 문항을 포함한 재풀이의 미채점 답안은 원복하고 이전 회차를 보관한다. 보관본 저장에 실패하면 원래 저장소를 덮어쓰지 않으며 저장이 회복된 뒤 보관본을 먼저 기록한다.

진행·제출한 모의시험은 원래 문항·해설·채점·답안·마감 시각을 보존하고, 다시 응시할 때 새 문항을 쓴다. 버전 메타정보는 시험 답안 원본 밖에 저장한다. 최초 원문과 중간 손계산 버전을 각각 보관하여 버전이 다른 기록에 같은 원문을 잘못 붙이지 않는다. 다중 탭에서 이전 상태가 들어와도 버전을 정규화한다.

[변경 답안 호환 UI 검사](final-audit/handcalc-revision-ui-results.json) 34개, [기본 오답 재풀이](final-audit/handcalc-retry-results.json) 51개, [재풀이 예외](final-audit/handcalc-retry-edge-results.json) 18개를 통과했다. 새 계산 안내가 O/X 답변 버튼과 겹치던 배치를 수정하고 모바일을 재검사했다. 전체 최신 화면·수식 결과는 25번을 따른다.

수정 전 문항의 채점 결과를 다른 내용으로 교체된 현재 문항의 정오 기록으로 가져오지 않는다. 내용이 바뀐 보관본 문항은 원래 시험에서 검토하고, 새 응시에서 최신 문제를 푼다. 현재 내용과 같은 이전 문항은 기존 오답 재풀이에 계속 연결한다. 이 버전 경계도 실제 UI에서 확인했다.
