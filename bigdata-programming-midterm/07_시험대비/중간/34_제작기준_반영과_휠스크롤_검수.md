# 제작 기준 반영·전체 영역 휠 스크롤 검수 (2026-10-25)

객관식·개념 단답형 재검수에서 사용한 기준을 기존 공통 제작/디자인 MD와 로컬 배포용 기준 사본에 반영했다. 코드 위에 포인터를 두면 세로 휠이 멈추던 원인도 수정했다. 커밋·푸시는 하지 않았다.

## 다음 과목에 적용할 기준

[기존 제작 가이드22절](../../../study-standards/03_시험대비_개념정리_및_문제출제_표준가이드.md#mc-short-semantic-audit)에 다음 내용을 추가하고 문서 상단에서 바로 찾도록 연결했다.

1. 강의자료·전사의 실제 평가 판단을 활성 문항의 지문·정답·해설에 연결한다. 태그/문항 수만으로 누락을 판정하지 않으며 오인식·범위 밖 내용·확인하지 못한 근거를 구분한다.
2. 객관식·단답 안과 유형 사이에서 코드/조건/답/추론이 같은 문제를 통합한다. 동일한 정답 단어라도 오류 원인·상태·평가 목적이 다른 문제는 구분한다. 제외 ID와 남긴 문항의 실제 질문/설명을 연결해 강조점을 보존한다.
3. 보기의 길이만 맞추지 않고 정보 단위·혼동 가능한 판단·유일 정답을 검수한다. 모든 오답 근거를 실제 코드·값으로 재계산하고, 변경된 값이 간단/상세 설명에도 반영됐는지 확인한다.
4. PDF를 따로 열지 않아도 같은 시험대비 창에서 모든 보기의 성립/실패 근거와 문항별 실행·상태·결론을 확인한다. 강의 용어 표기·허용 답안·수치/단위·채점 기준도 맞춘다.
5. 독립 기대값 실행, 공개 전 필수 자료/조건, 전체 활성 문항 검수, 실제 화면의 입력/채점·저장/재풀이와 수정 기록 보존을 확인한다. 역사적 보관본 검사와 현재 결과를 구분하며 다음 과목에 문항 수를 그대로 복사하지 않는다.

[디자인 가이드](../../../study-standards/02_시험대비_웹디자인_표준가이드.md#mc-short-explanation-ui)에는 보기/단답/상세 풀이 표시와 기록 보존 기준을, [휠 동작 기준](../../../study-standards/02_시험대비_웹디자인_표준가이드.md#pointer-independent-wheel-scroll)에는 포인터 위치와 무관한 세로 이동·내부 가로 읽기·실제 휠 검수 절차를 추가했다. 기존 본문과 배포용 사본의 경로 차이는 보존하고 새 기준은 동일하게 반영했다.

## 재현한 원인과 수정

`.code-scroll`에 지정한 `overscroll-behavior: contain`이 가로와 세로 양쪽의 스크롤 연결을 막고 있었다. 코드 자체에 세로로 넘치는 내용이 없어도 코드/빈칸 위에서 세로 휠이 상위 문제 카드로 전달되지 않았다. BP43에서 기존 CSS를 적용한 상태로 실제 포인터·휠을 보내 두 영역의 카드 위치가 그대로인 것을 재현했다.

가로 경계 제한은 X축에 유지하고 Y축은 기본 연결을 허용하도록 다음과 같이 수정했다.

```css
.code-scroll {
  overscroll-behavior-x: contain;
  overscroll-behavior-y: auto;
}
```

[레이아웃 원본](practice-source/style.css)과 [오프라인 시험대비 창](practice/index.html)에 함께 반영했다. 휠을 강제로 가로채는 JavaScript는 추가하지 않았다. 이번 Chromium 재현에서 완성할 동작·출력 영역은 기존에도 세로 이동했고, 코드/빈칸 영역은 실패했다. 수정 후 모든 대상 영역을 함께 검사했다.

## 실제 화면 확인

별도 Chromium 검수 프로필에서1440×800·390×844·320×740 화면을 사용했다. 실제 사용자 풀이 저장소는 건드리지 않았다.

- 목표 동작·출력·코드 제목/내용·입력칸·카드 여백, 준비 파일 제목/본문, 참조 표, 객관식 보기/보기별 설명, 단답 입력·상세 해설에 포인터를 놓고 세로 휠72회를 확인했다. 코드/입력칸의 위쪽 복귀도 따로 확인했다.
- 가로 시작/끝에서도 세로 이동이 이어졌다. 좁은 화면의 실제로 긴 BC26 코드에 가로 휠을 보내 내부 가로 위치만 이동하는지 확인했다. 가로로 넘치지 않는 코드는 불필요한 가로 이동이 없음을 확인했다.
- 빈칸에 작성 중인 값·커서/포커스·저장 상태와 북마크가 휠로 바뀌지 않았다. 새로고침 뒤 같은 기록을 유지했다. 인쇄 모드에서 본문/코드 overflow가 visible인 것도 확인했다.
- 총256개 확인을 통과했다. [실행 스크립트](output/playwright/wheel/audit-wheel.js), [실제 포인터/전후 위치 기록](output/playwright/wheel/browser-wheel.json), [검수 화면](output/playwright/wheel/fixed-desktop.png)을 남겼다. WebKit이나 실제 사용자 파일 창을 직접 조작해 검사한 결과로 제시하지 않는다.
