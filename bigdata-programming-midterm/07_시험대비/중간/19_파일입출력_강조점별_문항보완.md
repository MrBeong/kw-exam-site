# 파일 입출력 강조점별 문항 보완 · 2026-10-22

전사에 나온 내용이 개념/해설에 있다는 사실과, 학생이 문제에서 실제로 그 내용을 도출해야 한다는 사실을 분리해 재검토했다. 기존 문제의 지문·빈칸·정답·보기·목표 출력을 전사 BIG-023과 강의자료 BIG-019에 대조해 **코드 빈칸5·단답3·객관식4, 총12문항을 추가**했다.

[문제 풀기](practice/index.html) · [문제 MD](11_공지반영_예상문제.md) · [정답/문장별 해설](12_공지반영_정답과해설.md) · [전사 교정/대조](../../03_주차별정리/파일입출력_전사대조.md)

현재 문제은행은 **204문항(코드123·단답27·객관식54), 코드 빈칸318곳**이다. 학습용 문제은행의 수이며 실제 시험의 문항 수·유형별 배점을 뜻하지 않는다. 개념98군과 공지의 세 유형/표기 일치 채점 방식을 유지했다. 기존192문항의 모든 필드는 변경하지 않았다. GitHub 커밋·푸시는 하지 않았다.

## 직접 평가가 부족했던 부분

- 파일을 읽은 text의 슬라이스와 파일 객체의 읽기 위치를 구분하는 문제, 세 읽기 메서드를 같은 객체에서 혼합 호출하는 문제, seek(0)으로 되돌리는 빈칸이 부족했다.
- with 종료 뒤 이미 읽은 text가 남는다는 설명은 있었지만 그 자료형/사용을 직접 묻지 않았다.
- 사람별 total 초기화는 코드에 보였으나 빈칸이나 초기화 위치의 결과를 직접 평가하지 않았다.
- repr의 표시/원문 불변, strip이 쉼표를 자동 삭제하지 않r는다는 구분을 실제 출력 문제로 확인하지 않았다.
- x 모드의 선택과 FileExistsError 이름, 복사 루프의 읽기/쓰기 호출 횟수, bytes 내용 비교와 파일 크기 비교를 세부 평가 목표로 분리할 필요가 있었다.

이미 직접 평가하던 문자/바이트 길이, 경로, w 비우기 시점, 반복 누적, 개행, 전화번호 줄 번호, 시간 파싱, 텍스트 복사, 점수 파일 평균은 기존 문항을 유지했다. 빈 줄/EOF는 기존 코드 문제에 더해 약어 단답 유형을 보강했다. 불필요하게 같은 빈칸만 반복해 문항 수를 늘리지 않았다.

코드 빈칸은 제시한 교안 표기 기준으로 전체 일치해야 한다. 한 빈칸이라도 다르면 문항 전체 오답이며 부분점수는 없다. 다른 동등 코드가 실행상 가능하더라도 이 연습의 표기 기준과는 구분한다. BFC02의 마지막 읽기는 “현재 위치부터 끝까지 하나의 문자열”이라는 조건으로 read/readline 혼동을 피했고, BFC05는 피연산자를 제공하고 비교 연산자만 묻게 해 식의 순서 차이로 인한 불필요한 오답을 줄였다.

단답은 Python/슬라이드에서 실제 쓰는 str·EOF·FileExistsError만 답한다. 공백만 무시하며 대소문자·이름 표기는 정답 기준을 따른다. 임의의 영어 번역을 요구하지 않는다. 객관식은4지 단일 정답이며 모든 보기에 맞고 틀린 구체적 근거를 넣었다. 실제 시험의 문항별 배점은 미확인이므로 임의 점수를 붙이지 않았다.

## 코드·조건·해설 구성

- 모든 새 문항에 실제 Python 코드를 독립된 영역으로 제공한다. 들여쓰기·인코딩·읽기 순서·파일 상태를 보존했다. 필요한 파일만 문제에 표시한다.
- 파일 존재, 끝 개행, 같은 파일 객체를 계속 사용하는지, 복사 대상이 없는지, 정확한 바이트 수 등 답을 결정하는 조건을 함께 제공한다.
- 코드 빈칸에는 구현할 목표 동작과 출력이 있고, 출력/오류를 판단하는 단답·객관식에는 답인 결과나 예외명을 채점 전에 보여 주지 않는다. 명시적으로 정답/해설을 열면 열람할 수 있다.
- 12문항 모두 코드 문장별 설명을 제공한다. 객관식·단답의 문장별 해설 영역도 정답/해설 안에 넣었으며 인쇄할 때 펼쳐지고 이후 접힘 상태를 복원한다.
- BFC04는 교안 p.26의 입력/출력을 유지한다. BFM03의 간단한 두 줄 시간 자료와 바이트 비교용 ASCII 자료는 문제용 입력이라고 명시했다. 원래 강의 파일을 바꾸지 않는다. 무관한 이미지는 추가하지 않았다.

브라우저 검수는 과목 폴더를 임시 HTTP 서버로 제공한 후 별도 Playwright CLI 프로필의 practice/index.html에서 browser-file-assessment.js를 실행한다. 검수용 답안 fixture는 실제 사용자 풀이 브라우저에 넣지 않는다. 생성된 HTML만 고치지 않고 원본 모듈/빌더와 MD를 함께 유지한다.
