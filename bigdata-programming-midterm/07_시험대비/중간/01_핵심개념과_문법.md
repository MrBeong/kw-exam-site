> 눈에 보이는 코드가 아니라 실제로 실행된 코드와 현재 상태를 읽는다.

<a id="BD-001"></a>
### BD-001 · Python · 편집기 · 터미널의 역할

- Python 인터프리터는 코드를 실행하고 VS Code는 코드를 작성·관리하는 편집기다. Explorer는 파일 관리, Editor는 코드 작성, Terminal은 명령과 결과 확인 영역이다.
- `python hello.py`는 셸 명령이다. `.py` 파일이나 Python의 `>>>` 뒤에 적는 문장이 아니다. `>>>`와 셸 프롬프트는 코드에 포함하지 않는다.
- 대화형 모드는 짧은 실험에, `.py` 스크립트는 저장한 여러 줄을 다시 실행할 때 쓴다. 스크립트에서는 식만 적지 말고 결과가 필요하면 `print()`한다.

### BD-003 · 자동 표시 · print · 대입 · 저장

- 코드 셀의 마지막 표현식은 값을 자동 표시할 수 있다. 대입문은 값을 바꾸지만 자동 출력하지 않는다. 여러 결과를 보려면 `print()`를 쓴다.
- `x + 4`를 평가해 7을 보아도 `x`가 7로 바뀐 것은 아니다. 대입문이 없으면 `x`는 3이다.
- 편집·저장만으로 커널의 값이나 기존 출력이 새로 계산되지 않는다. `score = 80`을 90으로 편집만 하면 다음 출력은 여전히 85일 수 있고, 대입 셀을 재실행하면 95가 된다.

<a id="BD-004"></a>
### BD-004 · 실행 번호와 재시작

- A 셀 `x = 10`, B 셀 `print(x)`, C 셀 `x = 20`일 때 A→B는 10, A→C→B는 20이다. 화면 배치가 실행 순서가 아니다.
- 커널을 재시작하면 변수·함수 상태가 초기화된다. 코드가 화면에 남아 있어도 B만 실행하면 `NameError`가 날 수 있다.
- 재시작 후 위에서부터 모두 실행해도 같은 결과가 나오는지 확인한다. 이전 실행의 변수가 코드 누락을 가리지 않게 한다.

<a id="BD-005"></a>
### BD-005 · print와 문자열의 해석

- `print(10 + 20)`은 계산 결과 30, `print("10 + 20")`은 식 모양의 문자열을 출력한다.
- 여러 인수는 기본적으로 공백으로 나누고 마지막에는 줄바꿈을 붙인다. `print()`는 빈 줄, 문자열의 `\n`은 줄바꿈이다.
- `sep`은 인수 사이, `end`는 출력 끝에 붙는 문자열이다. 표시 방식을 바꾸어도 원래 값의 자료형은 그대로다.

교안 핵심 문장(발췌):

```python

print("Hello", end=" ")
print("Python")
```

### BD-012 · 변수는 이름, 대입은 연결

- 대입은 출력이 아니다. `x = 2 + 3`만으로 스크립트 화면에 5가 나타나지는 않는다.

### BD-013 · 재대입은 다른 이름을 자동 갱신하지 않는다

### BD-014 · int · float · str · bool

- `int`: 42, 0, -3 같은 정수. `float`: 3.14 같은 부동소수점 수. `str`: `"Python"`, `"42"`. `bool`: `True`, `False`. `type()`으로 확인한다.
- 10은 정수, `"10"`은 문자열이다. `10 + 3`은 13, `"10" + "3"`은 `"103"`, `"10" * 3`은 `"101010"`이다. 출력할 때 따옴표가 없어도 자료형은 다를 수 있다.
- float는 모든 실수를 정확히 저장하지 않는다. 문자열 `"True"`와 bool 값 `True`도 구분한다.

교안 핵심 문장(발췌):

```python
print(type(42))
print(type(3.14))
print(type("Python"))
print(type(True))
```

출력:

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
```

### BD-015 · 동적 타이핑

- 같은 이름에 int→float→str 객체를 다시 연결할 수 있다. 기존 정수 객체의 자료형을 바꾸는 것이 아니다.
- 동적 타이핑은 자료형끼리 자동 변환한다는 뜻이 아니다. 문자열에 `+ 1`을 하면 여전히 오류가 날 수 있다.

<a id="BD-016"></a>
### BD-016 · 다중 대입과 값 교환

- `x, y = 2, 3`은 순서대로 대응시킨다. 이 단순 형태에서 이름 수와 값 수가 다르면 `ValueError`다.
- `x, y = y, x`는 변경 전 오른쪽 두 값을 먼저 구하므로 2와 3이 3과 2로 교환된다.
- `x = y` 다음 `y = x`로 쓰면 첫 대입 후 x가 이미 바뀌어 둘 다 3이 된다.

```python
print(x, y)
```

```text

```

### BD-034 · while의 실행·종료 조건

### BD-038 · range의 시작·끝·간격

- 교안 형태에서는 위치 인수를 먼저 쓴다. `calc(10,x=20,z=30)`은 x에 두 번 전달해 TypeError다.

```python

    return length * width

print(rectangle_area())
print(rectangle_area(10))
print(rectangle_area(10, 5))
print(rectangle_area(width=5))
```

### BD-053 · 전역 읽기 · 지역 대입 · global

### BD-063 · remove · pop · del

- `remove(value)`는 값이 일치하는 첫 원소를 삭제하며 없으면 ValueError다. 값20을 지우는 것과 인덱스20을 지우는 것은 다르다.
- `pop()`은 마지막 원소, `pop(i)`는 i번 원소를 제거하고 그 값을 반환한다. 빈 리스트/범위 밖 위치는 IndexError다.
- `del data[i]`는 지정 위치 삭제 문장이다. 삭제 후 뒤 원소들의 인덱스가 바뀐다.
- 교안 [10,20,20,30]에서 remove(20)→[10,20,30], pop(1)은20 반환 후[10,30], del[0]→[30]이다.

교안 핵심 문장(발췌):

```python
data = [10, 20, 20, 30]
data.remove(20)
print(data)
taken = data.pop(1)
print(taken, data)
del data[0]
print(data)
```

### BD-077 · keys · values · items와 뷰

- `keys()`는 키, `values()`는 값, `items()`는 (키,값) 쌍의 뷰다. list로 바꾸면 그 시점의 별도 목록이다.
- 뷰는 원본 변화를 반영한다. 미리 만든 `keys_list`에는 이후 추가한 키가 자동 반영되지 않지만 `keys_view`에는 나타난다.
- `for key,value in d.items()`는 두 이름으로 푼다. 한 이름 `value`로 받아도 실제 값은 숫자만이 아니라 (키,값) 튜플이다. 변수명으로 자료형을 추측하지 않는다.

```python
print(list(keys_view))
print(keys_list)
print(list(d.items()))
```

출력:

```text

['foo', 'bar']
```

### BD-083 · 자료구조 선택과 변환

- list: 순서와 정수 인덱스, 변경 가능. tuple: 순서와 정수 인덱스, 원소 연결 불변. set: 중복 없는 원소·포함/집합 연산. dict: 키와 값 대응이다.
- set 변환은 중복/원래 순서 정보를 유지하지 않는다. sorted 결과는 리스트, list(d.items()) 결과는 튜플들의 리스트다.
- 종합 예제 values=[3,1,3]에서 ordered=sorted(values) 후 append(2)하면 values=[3,1,3,2], ordered=[1,3,3], unique길이3이다. d의 missing 조회0은 등록을 뜻하지 않는다.

교안 핵심 문장(발췌):

```python
values = [3, 1, 3]
ordered = sorted(values)
values.append(2)
unique = set(values)
d = {"count": len(values)}
print(values)
print(ordered)
print(len(unique))
print(d.get("missing", 0))
print("missing" in d)
print(d["count"])
```

출력:

```text
[3, 1, 3, 2]
[1, 3, 3]
3
0
False
```

### BD-084 · 메모리와 파일 · 문자와 바이트

- 변수는 실행 중 메모리에 있고 커널 재시작 후 자동 유지되지 않는다. 파일에 저장해야 다음 실행에서 읽을 수 있다. print만으로 결과 파일은 만들어지지 않는다.
- 텍스트도 저장 장치에서는 바이트다. 텍스트 모드는 인코딩으로 해석해 str, 이진 모드는 bytes를 제공한다.
- `"가"`의 길이는 문자1이고 UTF-8 인코딩 바이트 길이는3이다. 문자 수와 바이트 수는 다르다. 확장자만으로 인코딩을 확정할 수 없다.
- 문자 수와 바이트 수는 서로 다른 단위다. 저장 장치의 바이트를 텍스트 모드에서 지정 인코딩으로 해석해 str을 얻으며, 이진 모드는 bytes를 다룬다. 파일 확장자만 보고 인코딩이나 내용을 단정하지 않는다.

교안 핵심 문장(발췌):

```python
text = "가"
data = text.encode("utf-8")
print(len(text))
print(len(data))
```

출력:

```text
1
3
```

### BD-086 · 파일 객체와 열기 모드

- `open(...)`은 파일 객체를 반환한다. 파일명 문자열이나 파일 전체 내용과 다르며 열기 자체가 내용을 읽는 것은 아니다.
- r: 읽기, 없으면 오류. w: 없으면 생성하고 있으면 열 때 비움. a: 뒤에 추가. x: 새 파일 생성만 허용하고 이미 있으면 FileExistsError다. 기본 텍스트 읽기에서는 r을 생략할 수 있다.
- rb/wb/xb는 이진 모드다. w/wb는 write 이전 open 시점부터 원본을 잃을 수 있으므로 입력과 출력 경로를 분리한다.
- 같은 셀 재실행에서 a는 중복 추가, w는 교체, x는 두 번째 생성 실패다.
- `open()`의 r·w·a·x는 열기 모드이고, 파일 객체의 read()·write()는 연 뒤 수행하는 동작이다. 모드 r을 생략하면 기본은 읽기다.
- f·infile·src·dst는 파일 객체에 붙인 변수 이름이며 예약된 파일 명칭이 아니다. 어떤 이름을 쓰든 연 파일 객체에서 메서드를 호출한다.

### BD-087 · 읽기 위치 · EOF · seek

- 같은 파일 객체는 다음 읽을 위치를 기억한다. read()를 반복 호출해도 자동으로 처음부터 읽지 않는다.
- 텍스트 EOF에서 반환되는 값은 `""`, 이진은 `b""`다. 빈 줄 `"\n"`은 실제 한 문자 데이터라 EOF와 다르다.
- 다시 처음부터 읽으려면 재열기 또는 `seek(0)`을 사용한다. 한글 텍스트에서 tell값을 문자 인덱스처럼 임의 연산하지 않는다.
- 이미 읽은 text에 슬라이스를 적용하는 것은 메모리의 문자열을 고르는 연산이다. 파일 객체의 읽기 위치를 되돌리지 않는다. EOF 뒤 다시 읽으려면 파일을 다시 열거나 seek(0)을 사용한다.

```python
with open("letters.txt", encoding="utf-8") as f:
    first = f.read(2)
    rest = f.read()
    empty = f.read()
print(repr(first))
print(repr(empty))
```

출력:

```text
'A\n'
''
```

### BD-088 · read · readline · readlines · 반복

- `read()`는 현재 위치부터 끝까지 str, `read(n)`은 최대 n문자 str, `readline()`은 다음 한 줄 str, `readlines()`는 남은 줄 문자열들의 리스트다.
- `for line in f`는 남은 줄을 차례로 str로 받는다. 보통 줄 끝 `\n`도 포함된다. 줄 목록의 길이와 문자 수를 구분한다.
- 각 메서드를 비교할 때는 시작 위치를 같게 맞춘다. 앞선 read로 이미 EOF라면 뒤 메서드 결과가 비는 것은 정상이다.
- `text = infile.read()`로 받은 값은 화면에 여러 줄로 보여도 하나의 str이다. `text[:20]`은 인덱스0~19의 최대20문자를 고르며 개행도 한 문자로 센다. 줄 목록을 만드는 readlines()와 다르다.
- readline()은 임의의 줄 번호를 골라 주는 함수가 아니라 현재 위치의 다음 한 줄을 읽는다. readlines()는 그 위치부터 남은 줄 전체를 리스트로 받는다.

교안 핵심 문장(발췌):

```python
with open("blank.txt", encoding="utf-8") as f:
    for i in range(4):
        print(i + 1, repr(f.readline()))
```

출력:

```text
1 'A\n'
2 '\n'
3 'B\n'
4 ''
```

### BD-089 · 줄바꿈 · repr · strip

- line에 이미 `\n`이 있으면 `print(line)`이 기본 줄바꿈을 더해 빈 줄처럼 보인다. `print(line,end="")`는 추가 줄바꿈을 없앤다.
- `line.rstrip("\n")`은 오른쪽의 줄바꿈 제거, `strip()`은 양끝 공백류, 인수 없는 `rstrip()`은 오른쪽 공백류 제거다. 원본 파일을 수정하지 않고 새 문자열을 반환한다.
- `repr()`로 보이지 않는 공백·줄바꿈을 구별한다. 파일에 의미 있는 앞뒤 공백을 무조건 없애지 않는다.
- `repr()`는 보이지 않는 개행·탭·공백을 식별하는 표시 방법이다. 문자열이나 원본 파일의 내용을 바꾸지 않는다.
- 전사 보충(해당 슬라이드에는 미기재): `lstrip()`은 왼쪽 공백류를 제거하고 rstrip()은 오른쪽, strip()은 양끝을 제거한다. 기본 strip()은 공백류를 다루며 쉼표 같은 구두점을 자동으로 지우지 않는다. 공지의 슬라이드 한정 범위에 새 구두 보충 문법을 자동 포함하지 않는다.

교안 핵심 문장(발췌):

```python
line = "  Alice  \n"
print(repr(line))
print(repr(line.strip()))
print(repr(line.rstrip()))
print(repr(line.rstrip("\n")))
```

출력:

```text
'  Alice  \n'
'Alice'
'  Alice'
'  Alice  '
```

### BD-090 · close와 with의 범위

- 수동 방식은 open→read/write→close 순서다. with 구문의 들여쓴 범위가 끝나면 파일을 닫는다.
- with 안의 `f.closed`는 False, 밖은 True다. 닫힌 객체의 read는 ValueError다. 변수 f가 남았다고 열린 상태는 아니다.
- 쓰기 버퍼 반영과 자원 정리는 필요하지만 모든 장애에서 영구 저장을 보증한다는 뜻은 아니다.
- with를 벗어나면 파일이 닫히지만 f라는 이름이나 미리 읽은 text가 사라지는 것은 아니다. `print(f.closed)`와 `print(text)`는 가능하고, 닫힌 파일에서 f.read() 같은 입출력을 시도하면 ValueError가 난다.

### BD-092 · split · 슬라이스 · 중첩 누적

- hours 한 줄은 식별번호/이름/여러 시간 값이다. split 후 `fields[1]`은 이름, `fields[2:]`는 시간 문자열들이다.
- 시간만 float로 변환해 더한다. 사람마다 시간 항목 개수가 다를 수 있으므로 뒷부분을 반복한다.
- total=0.0은 사람을 처리하는 바깥 반복 안, 시간 반복 밖에서 초기화한다. Susan31.4/Brad36.8/Jenn39.5를 각각 출력한다.
- 파싱 전 실제 한 줄의 구분 문자를 확인한다. `split()`은 공백·탭 같은 공백류를 기준으로 나누며 소수점은 그대로 둔다. 소수점으로 split하면 시간 값 자체가 쪼개진다.

<a id="BD-093"></a>
### BD-093 · write의 인수 · 반환값 · 줄바꿈

- 텍스트 write는 str을 받는다. 숫자는 str()나 f-string으로 바꾼다. write는 줄바꿈을 자동 추가하지 않아 문자열에 `\n`을 직접 넣는다.
- `write("Hello")`, `write("Python")`은 HelloPython으로 붙는다. 첫 write의 반환값5는 쓴 문자 수이지 파일에 추가 저장한 숫자가 아니다.
- 기본 print()는 화면 출력, 파일 객체의 write()는 열린 파일에 기록하는 동작이다. 쓰기 모드 w는 첫 write를 하기 전, 파일을 여는 순간 기존 내용을 비운다. write()에 개행이 없으면 연속 기록한 문자열은 같은 줄에 붙는다.

교안 핵심 문장(발췌):

```python
with open("joined.txt", "w", encoding="utf-8") as f:
    n = f.write("Hello")
    f.write("Python")
print("첫 write의 반환값:", n)
with open("joined.txt", encoding="utf-8") as f:
    print(repr(f.read()))
```

출력:

```text
첫 write의 반환값: 5
'HelloPython'
```

### BD-095 · 텍스트 파일 복사와 비교

- 원본을 r로 열어 text=src.read()한 뒤 다른 경로를 x로 열어 dst.write(text)한다. 이미 있는 복사본은 덮어쓰지 않는다.
- 문자열 일치를 확인하는 것이지 모든 메타정보·저장 바이트까지 같다는 보장은 아니다. 인코딩/줄바꿈 변환이 개입할 수 있다.
- 텍스트 복사는 src.read()로 받은 str을 dst.write()로 기록하는 흐름이다. 원본/대상 경로를 구분하고 인코딩·줄바꿈 처리 때문에 텍스트 일치와 바이트 일치가 달라질 수 있음을 확인한다.

### BD-096 · 이진 복사와 종료 조건

- 이미지는 rb→xb로 bytes를 그대로 복사한다. 이진 모드에 encoding을 지정하지 않는다.
- `while True`에서 `block = src.read(1024)`, `if not block: break`, `dst.write(block)` 순서다. EOF의 b""를 쓰기 전에 종료한다.
- 2500바이트는1024/1024/452의 세 조각으로 기록되고 다음 read는0바이트다. 1024는 반복 횟수가 아니라 최대 읽을 바이트 수다.
- 겉모양 비교와 bytes 일치는 다르다. 원본·복사본을 rb로 읽어 비교한다. 제공 bridge 파일의 크기는 교안 화면 수치와 다르므로 강의의 고정 문제 값으로 취급하지 않는다.
- 2500바이트 예시는 데이터 조각3개(1024·1024·452)를 기록하고, 네 번째 read(1024)의 빈 bytes로 종료한다. EOF를 확인하는 읽기와 실제 데이터 기록 횟수를 구분한다.
- 1024는 이 예제의 한 번 읽기 상한이지 컴퓨터가 처리할 수 있는 파일 크기의 한계가 아니다. 큰 파일을 한꺼번에 메모리에 올리지 않는 블록 처리의 의미로 이해한다.

### BD-097 · 점수 파일 평균과 결과 저장

- total/count를 반복 전에0으로 초기화하고 반복 안에서 `total += int(line)`, `count += 1`을 수행한다. 평균은 반복문 밖에서 계산한다.

### BD-098 · 이 자료에서 다루는 오류와 범위 경계
