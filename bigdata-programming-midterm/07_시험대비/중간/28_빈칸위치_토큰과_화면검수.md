# 빈칸 위치·정답·해설 전수 검수 · 2026-10-25

검토한 코드131문항·316빈칸 중5문항에서 잘못된 부분 문자열을 가린 오류를 확인하고 수정했다. BP12의 전역r은 `result` 첫 글자가 아니라 `3.14 * r ** 2`의 피연산자이며,BE05/BP34의 int는 print 안의 글자가 아니라 실제 int 변환 호출이다.

| ID | 잘못 가린 대상 | 바로잡은 대상 |
|---|---|---|
| BC20 | `english_dict` 안의 `dict` | `english_dict = dict()`의 생성자 `dict` |
| BE05 | `print` 안의 `int` | `print(int(-1.75))`의 안쪽 `int` |
| BP12 | `result`의 첫 글자 `r` | `result = 3.14 * r ** 2`의 전역 변수 `r` |
| BP22 | `item_set` 안의 `set` | `item_set = set(item_list)`의 생성자 `set` |
| BP34 | `print` 안의 `int` | `print(int("10") + 3)`의 안쪽 `int` |

단순 첫 일치 검색이 단어 내부를 선택했고,기존의 ‘정답을 넣으면 원문으로 복원되고 실행된다’는 검사만으로 이 오류를 찾지 못했다. 잘못 가린 글자에 같은 정답을 넣어도 코드가 복원되기 때문이다. 완성 코드·정답 문자열·빈칸 번호·해설은 그대로이며5개 빈칸의 위치/템플릿만 바로잡았다.

## 원인과 생성 단계 수정

이전 작성본은 문항/답안 이력의 정확한 대조를 위해 보존한다. 현재 생성 단계에서는 명시한Python NAME토큰·줄·종류·텍스트로5개 위치를 해석하고,예상 좌표와 다른 소스나 모호한 후보는 오류로 처리한다. 그 뒤 **모든 활성316칸**을 토큰 검사에 통과시켜야 HTML/문제MD를 생성한다. 알려진5개를 고친다는 이유로 다른 부분 토큰을 허용하지 않는다.

- NAME·NUMBER·다중 문자OP의 일부를 가리거나 주석을 코드 대신 가리면 실패한다. 빈칸 번호·정답 문자열/좌표·겹침·템플릿·복원도 대조한다.
- 동일한 토큰이 반복되는7개 위치는 명시적으로 의미를 대조했다. 단어 빈도 코드의 조회 인수,원문range 시작값,중첩 리스트의 각 열,문자열 개행의 위치는 서로 구별한다.
- 문자열/서식의 의도한 부분 작성5개는 문항·번호·범위·이유를 고정해 검수했다. f접두부·진법/개행/서식 작성 등 정당한 과제와 단어를 잘못 자르는 경우를 혼동하지 않는다. 모든 문자열을 검사에서 빼는 예외는 없다.
- 웹UTF-16좌표 변환을 검사하고5개 수정 대상은 AST의실제 읽는이름/함수호출 역할도 확인했다. BP12의r은 거듭제곱의 피연산자다.
- 수정 전437개 레코드와 현재 레코드의 차이는 명시한5개 위치뿐이다. 이전426개 보존 검사와 빈칸 정리/예측문항 추가 검사는 이 명시적 위치 수정만 되돌려 대조한다. 일반 코드·보기·정답 변경을 허용하는 예외가 아니다.

작성 정책은 practice-source/blank-span-corrections.json,토큰 해석/검사는 blank_spans.py,빌더 연결은 blank-span-corrections.mjs와build.mjs다. raw작성본의 위치를 검증 없이 그대로 노출하는 생성 경로를 막았다.

## 기존 기록과 범위

437문항(코드131·단답244·객관식62)·316칸·원문19문항/52칸을 유지한다. 완성 코드·정답 문자열·번호/순서·실행 결과·기존 상세 해설은 동일하다. 해당5문항은 의도했던 개념/키가 그대로이고 위치만 바로잡은 것이므로 입력·정오·초안·북마크·진행 중 재풀이와 그prior를 그대로 보존한다. 새로고침 시 수정 전 문항/답안/정오를 ‘설정 → 수정 전 답안’에 한 번 보관하며 이력은 나중 입력 변경과 독립적이다.

437개 정오/초안 fixture와 진행 중 재풀이의 보존,회차 종료 시 이전 답안 복원,반복 새로고침의 중복 방지,오답 재풀이·재채점을 실제로 확인했다. 정답을 의미까지 바꾸는 수정과 단순 위치 수정을 같은 정책으로 일반화하지 않는다.

원본 자료는 수정하지 않았다. 이번 검수는 기존 강의자료/개념·실행 검증을 바탕으로 빈칸 위치와 정답·해설 대응을 전수 검사한 것이며,전체PDF를 새로 시각 검수했다는 뜻은 아니다. 미확보 추가Notebook·교수 실제 정답표·최종 출제 경계의 한계는 유지한다.
