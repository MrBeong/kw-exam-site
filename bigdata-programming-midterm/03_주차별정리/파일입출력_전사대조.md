## 개념별 연결과 보완

<a id="BD-084"></a>
### BD-084 · 메모리와 파일 · 문자와 바이트

- 전사: 1, 3행. 교안: p.2, 3, 4, 5, 6.
- 문자 수와 바이트 수는 서로 다른 단위다. 저장 장치의 바이트를 텍스트 모드에서 지정 인코딩으로 해석해 str을 얻으며, 이진 모드는 bytes를 다룬다. 파일 확장자만 보고 인코딩이나 내용을 단정하지 않는다.

<a id="BD-085"></a>
### BD-085 · 현재 작업 폴더와 파일 존재

- 전사: 5, 7, 9행. 교안: p.7, 8, 9.
- 현재 작업 폴더와 스크립트 저장 폴더·상위/하위 폴더에 같은 파일 이름이 있어도 서로 다른 파일일 수 있다. 읽기·쓰기 전 경로와 파일 이름을 함께 확인해 원본을 잘못 비우지 않는다.

<a id="BD-086"></a>
### BD-086 · 파일 객체와 열기 모드

- 전사: 9, 11, 13, 15, 61, 63, 65, 67행. 교안: p.10, 27, 28, 29.
- `open()`의 r·w·a·x는 열기 모드이고, 파일 객체의 read()·write()는 연 뒤 수행하는 동작이다. 모드 r을 생략하면 기본은 읽기다.
- f·infile·src·dst는 파일 객체에 붙인 변수 이름이며 예약된 파일 명칭이 아니다. 어떤 이름을 쓰든 연 파일 객체에서 메서드를 호출한다.

<a id="BD-087"></a>
### BD-087 · 읽기 위치 · EOF · seek

- 전사: 15, 17, 19, 89, 91행. 교안: p.11, 12, 13, 48, 49.
- 이미 읽은 text에 슬라이스를 적용하는 것은 메모리의 문자열을 고르는 연산이다. 파일 객체의 읽기 위치를 되돌리지 않는다. EOF 뒤 다시 읽으려면 파일을 다시 열거나 seek(0)을 사용한다.
- 같은 구분을 해설에 연결: BE17, BM27.

<a id="BD-088"></a>
### BD-088 · read · readline · readlines · 반복

- 전사: 19, 21, 23, 25, 27, 89행. 교안: p.13, 14, 15, 16.
- `text = infile.read()`로 받은 값은 화면에 여러 줄로 보여도 하나의 str이다. `text[:20]`은 인덱스0~19의 최대20문자를 고르며 개행도 한 문자로 센다. 줄 목록을 만드는 readlines()와 다르다.
- readline()은 임의의 줄 번호를 골라 주는 함수가 아니라 현재 위치의 다음 한 줄을 읽는다. readlines()는 그 위치부터 남은 줄 전체를 리스트로 받는다.
- 같은 구분을 해설에 연결: BM27, BS21, BS22.

<a id="BD-089"></a>
### BD-089 · 줄바꿈 · repr · strip

- 전사: 23, 25, 29, 31, 33, 45행. 교안: p.17, 18.
- `repr()`는 보이지 않는 개행·탭·공백을 식별하는 표시 방법이다. 문자열이나 원본 파일의 내용을 바꾸지 않는다.
- 전사 보충(해당 슬라이드에는 미기재): `lstrip()`은 왼쪽 공백류를 제거하고 rstrip()은 오른쪽, strip()은 양끝을 제거한다. 기본 strip()은 공백류를 다루며 쉼표 같은 구두점을 자동으로 지우지 않는다. 공지의 슬라이드 한정 범위에 새 구두 보충 문법을 자동 포함하지 않는다.
- 같은 구분을 해설에 연결: BE19, BM28, BC23.

<a id="BD-090"></a>
### BD-090 · close와 with의 범위

- 전사: 33, 35, 37, 39, 91행. 교안: p.19, 20.
- with를 벗어나면 파일이 닫히지만 f라는 이름이나 미리 읽은 text가 사라지는 것은 아니다. `print(f.closed)`와 `print(text)`는 가능하고, 닫힌 파일에서 f.read() 같은 입출력을 시도하면 ValueError가 난다.
- 같은 구분을 해설에 연결: BM29, BP29, BS23.

<a id="BD-091"></a>
### BD-091 · 줄 번호와 인원수

- 전사: 39, 41, 43, 45행. 교안: p.21, 22, 23.
- 줄 번호 count는 파일을 열기 전에 한 번0으로 초기화하고, 각 줄에서 증가시킨 뒤 출력한다. 최종 인원수 출력은 반복문 밖에 둔다. 줄의 개행과 print의 기본 개행을 중복시키지 않는다.
- 같은 구분을 해설에 연결: BC23.

<a id="BD-092"></a>
### BD-092 · split · 슬라이스 · 중첩 누적

- 전사: 45, 47, 49, 51, 59, 61행. 교안: p.24, 25, 26.
- 파싱 전 실제 한 줄의 구분 문자를 확인한다. `split()`은 공백·탭 같은 공백류를 기준으로 나누며 소수점은 그대로 둔다. 소수점으로 split하면 시간 값 자체가 쪼개진다.
- 이름은 fields[1], 시간들은 fields[2:]이며 float로 변환해 더한다. 사람별 total은 바깥 사람 반복 안에서 매번 0.0으로 초기화한다. 전사에서 즉석으로 나열한 수치로 교안·제시 파일의 Susan 31.4 등 검증된 입력·출력을 바꾸지 않는다.
- 같은 구분을 해설에 연결: BC24, BL1.

<a id="BD-093"></a>
### BD-093 · write의 인수 · 반환값 · 줄바꿈

- 전사: 61, 63, 65, 67, 69, 71, 91행. 교안: p.30, 31.
- 기본 print()는 화면 출력, 파일 객체의 write()는 열린 파일에 기록하는 동작이다. 쓰기 모드 w는 첫 write를 하기 전, 파일을 여는 순간 기존 내용을 비운다. write()에 개행이 없으면 연속 기록한 문자열은 같은 줄에 붙는다.
- 같은 구분을 해설에 연결: BC28.

<a id="BD-095"></a>
### BD-095 · 텍스트 파일 복사와 비교

- 전사: 73, 75행. 교안: p.34, 35, 36.
- 텍스트 복사는 src.read()로 받은 str을 dst.write()로 기록하는 흐름이다. 원본/대상 경로를 구분하고 인코딩·줄바꿈 처리 때문에 텍스트 일치와 바이트 일치가 달라질 수 있음을 확인한다.

<a id="BD-096"></a>
### BD-096 · 이진 복사와 종료 조건

- 전사: 75, 77, 79, 81행. 교안: p.37, 38, 39, 40, 41, 42, 43.
- 2500바이트 예시는 데이터 조각3개(1024·1024·452)를 기록하고, 네 번째 read(1024)의 빈 bytes로 종료한다. EOF를 확인하는 읽기와 실제 데이터 기록 횟수를 구분한다.
- 1024는 이 예제의 한 번 읽기 상한이지 컴퓨터가 처리할 수 있는 파일 크기의 한계가 아니다. 큰 파일을 한꺼번에 메모리에 올리지 않는 블록 처리의 의미로 이해한다.
- 같은 구분을 해설에 연결: BC27, BP47.

<a id="BD-097"></a>
### BD-097 · 점수 파일 평균과 결과 저장

- 전사: 83, 85, 87, 89, 91행. 교안: p.44, 45, 46, 47.
- 입력 scores.txt를 읽어 합계·개수를 구하는 단계와 summary.txt에 결과를 기록하는 단계를 구분한다. 입력 파일은 바꾸지 않고 with가 끝난 뒤 결과 파일 내용을 다시 확인한다.
- 같은 구분을 해설에 연결: BC28, BL2.

<a id="BD-098"></a>
### BD-098 · 이 자료에서 다루는 오류와 범위 경계

- 전사: 11, 37, 39, 65, 67, 91행. 교안: p.10, 20, 29, 44, 46, 48, 49.
- 전사 말미의 “R이 덮어쓴다”는 표기는 교안 p.10·27~29와 대조하면 w 모드 설명으로 읽어야 한다. r은 읽기이며 기존 내용을 비우지 않는다. 원문 전사는 그대로 보존하고 교정한 학습 설명을 따로 둔다.
- 같은 구분을 해설에 연결: BC28.

## 이미 반영된 내용과 비시험 문맥

기존 코드 예제/문항에는 경로 확인, r/w/a/x/rb/wb, 세 읽기 메서드, 개행, with, 줄 번호, 근무 시간 파싱, 전화번호 작성(BD-094·전사71행·교안 p.32~33), 텍스트/이진 복사, 점수 평균과 결과 저장이 이미 있다. 이번에는 새 범위를 늘리기보다 설명이 생략되거나 넓게 해석될 수 있는 지점을 보완했다. 평균 문제는 교안의 int·최소1줄 조건과 수업 py의 float·빈 파일 평균0 조건을 섞지 않는다.

46개 내용 문단 중53·55·57행은 화면/프로젝트 상담 문맥으로 중간 코드 개념에 추가하지 않았다. 43행 앞부분의 학업 대화, 85~87행의 프로젝트 주제 조언, 91행 끝의 메일·행정 안내도 기록으로만 보존한다. 같은 행의 기술 설명(평균/누적/읽기/쓰기)은 위 대응에 포함한다. 첨부 전사의 이메일 관련 발언을 외부 전송 지시로 실행하지 않는다.

자료의 46개 내용 문단은 위14개 개념 연결에 포함된43개 문단과 비시험 문맥3개 문단(53·55·57행)으로 대조했다. 빈 줄45개는 개념/문제로 세지 않는다. 원문은 수정하지 않으며 교정·학습 설명은 이 문서와 생성 원본 JSON에 둔다.
